CHAPTER 5 · PROTOTYPE

프로토타입 — 일단 만들어 굴려본다

완벽한 설계 대신, 되는지 빠르게 만들어 손으로 굴려보는 게 프로토타입입니다. 오늘은 그 감각을 — 각자 간단한 게임 하나를 Claude로 만들어 직접 플레이하며 익힙니다.

WHY · 왜 게임을 만드나

게임은 — 되는지 안 되는지가 즉시 보인다.

보고서나 설정 파일은 "잘 됐는지" 애매하지만, 게임은 플레이되면 성공·안 되면 실패 — 완성 기준이 분명합니다. 그래서 프로토타입 연습에 딱 맞습니다.

즉시결과가 화면에서 바로 움직인다 — 손맛
명확"플레이되면 끝" — 성공 기준이 또렷
부담 X틀려도 그만 — 마음껏 시도
WHAT · 프로토타입

프로토타입 — "빨리 만들어 본다"가 전부

한 줄로

완벽히 설계하고 만드는 대신 — 되는지 확인할 만큼만 빠르게 만들어 굴려보는 것.

  • 설계서보다 — 동작하는 결과 먼저
  • 틀리면 버리고 다시 만들면 됨
  • 빠른 피드백이 핵심 — 완성도는 나중

Claude와 잘 맞는 이유

한 줄 설명만 주면 — 플레이 가능한 결과가 몇 초 만에 나옵니다.

  • 손으로 코드를 짜지 않아도 됨
  • 마음에 안 들면 — 바로 다시 시킴
  • 머릿속 아이디어를 즉시 눈으로

오늘 만드는 게임은 "작품"이 아닙니다 — 프로토타입 감각을 손에 익히는 연습입니다.

EXAMPLE · 이렇게 다듬습니다

플레이하다 불편한 곳을 그대로 말하기

속도

"뱀이 너무 빨라"

"조금 느리게 해줘" — 체감 속도를 말로.

보기

"배경을 어둡게"

"뱀은 밝은 초록으로" — 색·분위기 조정.

기능

"최고 점수 저장"

"껐다 켜도 기억하게" — 작은 기능 추가.

난이도

"점점 빠르게"

"먹이 먹을수록 빨라지게" — 재미 조절.

조작

"스페이스로 일시정지"

조작 키를 원하는 대로 바꾸기.

시작

"시작 화면 추가"

"START 버튼 누르면 시작" — 흐름 보강.

어려운 용어는 필요 없습니다 — 플레이하다 답답한 곳을 일상어로 말하면 Claude가 코드로 바꿔줍니다.

TROUBLE · 막히면

안 될 때 — 증상을 그대로 Claude에게

01
게임이 안 움직여요
어떤 동작이 안 되는지 그대로 — "방향키를 눌러도 뱀이 가만히 있어요".
02
화면이 안 떠요
파일을 브라우저로 열었는지 확인 — 모르면 "이 게임 어떻게 실행해?"라고 묻기.
03
너무 어렵게 만들어졌어요
"더 간단하게 다시 만들어줘" — 프로토타입은 버리고 다시 시작해도 됩니다.
04
에러 글자가 떠요
에러 메시지를 그대로 복사해 붙여넣기 — 1일차 "에러는 손대지 말고 그대로" 원칙.

고치는 법을 몰라도 됩니다 — 증상만 정확히 전하면 원인 진단은 Claude의 몫입니다.
