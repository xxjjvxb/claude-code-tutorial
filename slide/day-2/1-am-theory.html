PART A · GIT 안전벨트

Git — 망쳐도 되돌릴 수 있다

AI가 파일을 마음대로 고치는 시대일수록 버전 관리는 옵션이 아니라 필수. 명령 4개만 있으면 충분합니다.

DEFINITION · Git이 뭔가

코드의 시간여행 장치입니다.

파일이 어떻게 바뀌어 왔는지 기록하고, 원하는 시점으로 되돌릴 수 있는 도구. 여러 명이 같이 작업할 때도 충돌 없이 합쳐줍니다.

기록파일이 변할 때마다 스냅샷으로 저장
복원"3시간 전으로 돌려줘" — 한 줄이면 끝
협업여러 명의 변경을 충돌 없이 합치기
WHY · AI 시대의 Git

AI가 파일을 직접 고치는 시대 — 안전벨트입니다

× Git 없이 AI 시키기
"여러 파일 한꺼번에 수정해줘"
✓ 5개 파일 수정 완료
...어 뭔가 망가짐
어디부터 어디까지 바뀐 건지 모름
되돌릴 길이 없음

한 번 잘못 시키면 복구 불가. 손이 떨리면서 일을 시키게 됩니다.

✓ Git과 함께
git commit (직전 상태 저장)
"여러 파일 한꺼번에 수정해줘"
✓ 5개 파일 수정 완료
망가졌으면 → git restore .
5초 만에 직전으로 복귀

되돌릴 수 있다는 감각이 있을 때만 AI에게 큰 일을 맡길 수 있습니다.

CONCEPT · 헷갈리지 말 것

Git ≠ GitHub — 완전히 다른 것

Git · 도구 (내 컴퓨터에)

버전 관리 프로그램 자체

  • 내 컴퓨터에서 동작
  • 인터넷 없이도 됨
  • 명령어: git init git commit
  • 오픈소스 · 누구나 무료
GitHub · 서비스 (인터넷에)

Git 저장소를 클라우드에 두는 곳

  • 웹사이트 — github.com
  • 여럿이 같은 코드를 공유
  • Microsoft 운영 (유료/무료)
  • "Git의 인스타" 같은 SNS 측면도

오늘은 Git만 배우고, GitHub 가입까지만 합니다. 본격적으로 push/pull은 미니프로젝트 때.

CORE FLOW · 핵심 흐름

매일 쓰는 Git 명령은 딱 4개

01
init
한 번만. 폴더를 Git으로 추적 시작.
PS> git init
02
status
"지금 어떤 변화가 있나" 확인.
PS> git status
03
add
저장할 파일들을 모은다.
PS> git add .
04
commit
스냅샷 + 메시지로 영구 저장.
PS> git commit -m "메시지"

02 → 03 → 04 사이클이 매일 반복됩니다. 작업 한 덩어리 끝날 때마다 commit — 하루에 5–10번 정도.

DEEP · git init / git status

시작하고, 확인하는 명령

git init — 한 번만

현재 폴더를 Git이 추적하는 저장소로 만든다. 숨김 폴더 .git이 생성됨.

  • 이미 init된 폴더에 또 하면 → 그냥 무해함
  • .git 폴더 지우면 → 추적 끝
PowerShell — Day1/
PS> git init Initialized empty Git repository in C:\Users\you\Desktop\Day1\.git\PS> git status On branch main No commits yet Untracked files: about.html style.css

git status는 막혔을 때 가장 먼저 치는 명령 — 지금 상태가 어떤지 알려줍니다.

DEEP · git add / git commit

변경사항을 스냅샷으로 저장

add — 저장할 파일 모으기

변경된 파일 중 커밋에 포함시킬 것들을 선별해서 staged 영역에 올린다.

  • git add . — 모든 변경 다 포함
  • git add about.html — 특정 파일만

commit — 영구 저장

staged 영역의 내용을 스냅샷으로 박제. 메시지 한 줄 필수.

  • -m "메시지"로 한 줄 설명
  • 좋은 메시지: "자기소개 페이지 첫 버전"
한 사이클 — add → commit
PS> git add .PS> git commit -m "자기소개 페이지 첫 버전" [main (root-commit) a3f1b2c] 자기소개 페이지 첫 버전 2 files changed, 124 insertions(+)
UNDO · 되돌리기

망친 파일 한 줄로 원복.

commit 이후의 변경을 직전 commit 상태로 되돌리는 명령. AI가 잘못 고친 직후 가장 자주 씁니다.

파일git restore about.html — 그 파일만
전부git restore . — 모든 변경 통째 취소
규칙commit하지 않은 변경은 한 번에 사라짐 — 신중히

4개 모두 입력 첫 글자에서 시작 — 손가락이 자동으로 가야 합니다.

/INIT — 가장 자주 첫 명령

새 폴더 들어가면
/init 부터.

현재 폴더의 파일 구조 · 코드를 Claude가 훑은 뒤 CLAUDE.md 초안을 자동 생성. 거기서부터 본인 입맛대로 다듬으면 끝.

1폴더 진입 → claude 실행
2/init 입력 → 30초~2분 분석
3CLAUDE.md 생성됨 → 한국어 답변 등 추가
@ MENTION — 컨텍스트에 끼워 넣기

"이 파일 좀 봐줘"의 정식 표현.

파일 내용을 매번 복사·붙여넣기 할 필요 없음. @로 가리키기만 하면 Claude가 그 파일을 직접 읽어서 답변에 반영합니다.

파일@about.html — 그 파일 한 개
폴더@tests/ — 폴더 안 모든 파일
자동완성@ 친 뒤 Tab — 폴더 트리에서 선택
! SHELL — 셸 명령 즉석 실행

claude를 나가지 않고 PowerShell.

대화 중간에 셸 명령을 한 번 돌리고 싶을 때. !로 시작하면 그 줄은 PowerShell이 직접 실행. 결과는 다음 응답에 자동 포함됩니다.

자주!git status · !git log · !ls
주의처음 쓸 땐 권한 prompt — 한 번 read해보고 승인
결과 활용"방금 실행한 결과 보고 분석해줘" 가능
