준비 · git 설치 + 신원 등록

먼저 — git 설치하고 신원 등록

git-scm.com에서 받기

git-scm.com/download/win ↗

노란색 "Git for Windows/x64 Setup" 클릭 → 받은 파일 실행 → 옵션은 전부 기본값으로 Install. 끝나면 PowerShell을 새로 엽니다.

PowerShell — 새 창에서
# 설치가 됐는지 — 버전 확인PS> git --version git version 2.49.0.windows.1# 커밋에 남길 신원 — 최초 1회만PS> git config --global user.name "홍길동"PS> git config --global user.email "hong@example.com"

설치 마법사는 옵션이 많지만 전부 기본값으로 두면 됩니다. 신원을 등록하지 않으면 첫 커밋에서 *** Please tell me who you are 에러 — git config 두 줄이면 해결, 평생 한 번만.

STEP 01 · git init

어제 폴더를 Git 저장소로

3가지만 하면 됨

  1. VS Code → File → Open Folder → Day1
  2. 통합 터미널 (Ctrl + `) 열기
  3. git init 입력 → 엔터
PowerShell — Day1/
PS> git init Initialized empty Git repository in C:\Users\you\Desktop\Day1\.git\# 폴더에 숨김 .git 폴더가 생성됨# VS Code에서 좌측 사이드바에 변화

VS Code 좌측 사이드바에 Source Control 아이콘 (Y자 모양)이 활성화되면 성공. 거기서도 git을 GUI로 다룰 수 있습니다.

STEP 02 · 첫 커밋

status → add → commit 한 사이클

PowerShell — Day1/ — 첫 커밋 한 사이클
# 1) 지금 어떤 상태인지PS> git status Untracked files: about.html, style.css, CLAUDE.md# 2) 모든 변경 staged 영역에 올림PS> git add .# 3) 다시 status — staged 확인PS> git status Changes to be committed: new file: about.html, style.css, CLAUDE.md# 4) 커밋 — 메시지 한 줄PS> git commit -m "자기소개 페이지 첫 버전" [main (root-commit) a3f1b2c] 자기소개 페이지 첫 버전 3 files changed, 219 insertions(+)

커밋 메시지는 한국어 OK. "오늘 한 일을 한 줄로" 정도면 충분.

STEP 03 · / 슬래시

/model 로 모델 전환

해보기

  1. 같은 터미널에서 claude 실행
  2. /model 입력 → 엔터
  3. 리스트에서 Haiku 선택
  4. "안녕" 한 번 → 응답 속도 체감
  5. 다시 /model → Sonnet으로 복귀
claude — Day1/
> /model Select a model: > haiku (빠르고 저렴) sonnet (현재) ← 강의 기본 opus (느리지만 똑똑) ✓ haiku 로 변경됨> 안녕 안녕하세요! (응답이 더 빠름)

Haiku는 짧은 답변·반복 작업에. 강의 기본은 Sonnet — 다 끝나면 Sonnet으로 돌려놓고 다음 단계로.

STEP 04 · @ 멘션

@about.html 분석 시키기

실험할 것

  1. claude 입력란에 @ 입력
  2. Tab 누르면 폴더 트리 자동완성
  3. about.html 선택 → 한 칸 띄고 "분석해줘"
  4. 결과: 디자인 톤·구조 분석 응답

변형 시도

  • @style.css 색상 팔레트 정리해줘
  • @about.html 글자 좀 키워줘
  • @. — 현재 폴더 전체 컨텍스트

@ 자동완성에 익숙해지면 매번 파일 경로 외울 필요가 없어집니다 — Tab만 누르면 됨.

STEP 05 · ! 셸 실행

대화 중간에 PowerShell 호출

claude — Day1/
# 1) 셸 명령 즉석 실행> !git log ⚠ Claude wants to run: git log [ Allow once / Always allow / Deny ] → "Allow once" 선택 $ git log commit a3f1b2c (HEAD -> main) Date: ... 자기소개 페이지 첫 버전# 2) 그 결과 활용> 방금 git log 결과 보고, 다음 작업 제안해줘 현재 첫 커밋만 있네요. 다음 단계로: · style.css에 hover 효과 추가 · 두 번째 커밋으로 분리해 저장

처음 !를 쓰면 권한 prompt가 뜹니다 — "Allow once"가 가장 안전. "Always allow"는 나중에 신뢰가 쌓인 명령에만.

STEP 06 · # 메모

CLAUDE.md에 한국어 규칙 추가

3개 추가해보기

  1. # 항상 한국어로 답해줘
  2. # 코드 블록은 마크다운으로
  3. # 변수명은 영어, 주석은 한국어

매번 "프로젝트 (Day1/CLAUDE.md)" 선택.

확인

  • VS Code 사이드바에서 CLAUDE.md 열기
  • 방금 추가한 3줄 보임
  • /memory 명령으로도 진입 가능
  • 한 번 적은 규칙은 매 세션 자동 주입

CLAUDE.md는 200줄 넘기면 신호대잡음비 ↓ — 짧고 명확한 규칙만 적습니다 (Day 3에서 자세히).

STEP 07 · AI에게 git 시키기

"지금까지 작업 커밋해줘"

claude — Day1/
> 지금까지 작업 커밋해줘 변경 사항을 확인합니다. ⚠ Claude wants to run: git status → 승인 CLAUDE.md에 답변 규칙 3개 추가됨. 커밋 메시지를 제안드립니다: → "CLAUDE.md에 답변 규칙 추가" ⚠ Claude wants to run: git add . && git commit -m "..." → 메시지 OK? 승인 ✓ [main b8c9d4e] CLAUDE.md에 답변 규칙 추가 1 file changed, 4 insertions(+)

처음으로 AI가 본인 손 대신 git을 다루는 순간. 권한 prompt 뜨면 메시지 한 번 읽고 승인 — 무지성 X.

BONUS · 되돌리기 한 가지 더

AI가 망쳤을 때 — ESC 두 번

ESC 두 번이 하는 일

  • claude 대화 중 ESC를 두 번 누르기
  • Claude가 편집한 파일이 편집 직전 상태로 복원
  • 대화는 그대로 — 코드만 되돌아감
  • 커밋을 안 했어도 OK — 세션 안의 빠른 되돌리기

git restore와 무엇이 다른가

  • git restore — 마지막 커밋 시점으로
  • ESC 두 번 — Claude가 고치기 직전으로
  • 커밋 전이라 git restore가 못 잡는 변경도 ESC로
  • 둘 다 알아두면 어떤 상황에서도 되돌릴 수 있음

단, ESC 두 번은 Claude가 편집한 파일만 되돌립니다 — 본인이 직접 고친 것이나 터미널 명령의 결과는 대상이 아닙니다.
