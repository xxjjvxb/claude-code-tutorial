SUBAGENT · 도우미

서브에이전트 — 파일 하나가 도우미 하나

왜 + 무엇

메모장 하나에도 화면·데이터·로그인이 섞입니다. 한 대화에 다 시키면 맥락이 엉키죠 — 역할을 떼어 도우미에게 맡깁니다.

  • .claude/agents/의 .md 파일 하나 = 도우미 하나
  • 역할·규칙·쓸 모델을 사람 말로 적음
  • 메인 대화는 깨끗하게 — 위임 작업은 따로
.claude/agents/ui-helper.md
--- name: ui-helper--- model: sonnet너는 화면 담당이다. 단순하고깔끔한 메모장 화면을 만든다.기능은 적게, 보기 쉽게.

CLAUDE.md·슬래시를 써본 그 감각 그대로 — 사람 말로 역할을 적으면 도우미가 됩니다. Claude에게 부탁해 만들고, 입력창에 @를 쳐서 목록으로 확인합니다.

CALL · 부르는 두 가지 방법

알아서 위임 — 또는 @로 지목

자동 위임

Claude가 알아서 부른다

  • 요청 내용이 어떤 도우미와 맞으면 — 알아서 위임
  • "메모장 화면 만들어줘" → 화면 도우미가 호출
  • 도우미 설명을 잘 적어둘수록 정확
@멘션 — 명시 호출

내가 직접 지목한다

  • @ui-helper 메모 입력칸 만들어줘
  • 어떤 도우미에게 맡길지 확실할 때
  • 2장에서 배운 @ 문법 그대로

처음엔 @멘션으로 명시 호출이 편합니다 — 누가 일했는지 눈에 보여서 감을 잡기 좋습니다.

핵심은 역할 설명(describe) — 도우미별 설명문은 뒤 세 장에서 그대로 복사해 쓰고, 도구 권한은 바로 다음 장에서 봅니다.

PERMISSION · 도구 권한

이 도우미가 — 쓸 도구를 고른다

.claude/agents/ui-helper.md
---name: ui-helperdescription: 화면(HTML·CSS) 담당 도우미# tools: 줄이 없으면 → 모든 도구 사용---(아래에 역할 설명 본문)

어떻게 대응할까

도우미가 쓸 도구는 .md 파일 머리(frontmatter)의 tools: 줄로 정합니다.

  • 메모장 도우미는 화면을 만들고(편집)·실행하고·읽어야 함
  • 그러니 tools: 줄 없이(=전체 허용) 두면 막힘없이 일함
  • 익숙해지면 — tools: Read, Edit처럼 필요한 것만 좁히기

Claude에게 부탁하면 이 파일도 알아서 만들어 줍니다 — 확인만 하면 됩니다.

권한은 "도우미가 일하다 막히지 않게" — 처음엔 넉넉히(All tools), 나중에 줄이는 게 편합니다.

AGENT ① · 화면 담당

도우미 ① — 화면 담당 ui-helper

이 도우미는

메모장의 화면(UI)만 만드는 도우미입니다.

  • 모델 — Sonnet
  • 맡는 것 — 입력칸 · 메모 목록 · 수정·삭제 버튼
  • 안 맡는 것 — 데이터 저장 · 로그인
ui-helper · describe 
너는 메모장 앱의 화면만 담당한다.
메모 입력칸, 저장된 메모 목록, 수정·삭제 버튼을 만든다.
화면은 단순하고 깔끔하게 — 한눈에 보이게.
데이터 저장·로그인은 다른 도우미 몫 — 건드리지 않는다.

describe는 사람 말로 — 위 문장을 그대로 적으면 됩니다. 맡는 것과 안 맡는 것을 분명히 적을수록 도우미가 정확해집니다.

AGENT ② · 데이터 담당

도우미 ② — 데이터 담당 data-helper

이 도우미는

메모를 Supabase에 저장하는 일을 맡습니다.

  • 모델 — Sonnet
  • 맡는 것 — Supabase 연결 · 메모 CRUD(추가·조회·수정·삭제)
  • 안 맡는 것 — 화면 디자인 · 로그인
data-helper · describe 
너는 메모장의 데이터 저장을 담당한다.
Supabase에 메모를 저장·조회·수정·삭제(CRUD)한다.
메모를 쓰면 Supabase에 저장하고, 앱을 열면 저장된 메모를 불러온다.
Supabase 키는 환경변수로 — 코드에 직접 적지 않는다.

데이터 도우미는 — "어디에(Supabase), 무엇을(메모 CRUD), 어떻게(키는 환경변수)"를 분명히. 화면 이야기는 빼고 데이터에만 집중하게.

AGENT ③ · 로그인 담당

도우미 ③ — 로그인 담당 login-helper

이 도우미는

구글 로그인을 붙이고, 로그인 안 하면 막는 일을 맡습니다.

  • 모델 — Sonnet
  • 맡는 것 — 구글 로그인 버튼 · 로그인 전 접근 차단
  • 안 맡는 것 — 화면 디자인 · 데이터 저장
login-helper · describe 
너는 메모장의 구글 로그인을 담당한다.
"구글로 로그인" 버튼을 만들고, 로그인 안 하면 메모를 못 보게 막는다.
로그인한 사람은 자기 메모만 보이게 한다.
로그인은 Supabase 기능을 쓴다.

로그인 도우미는 — "구글로, Supabase 기능으로, 로그인 전엔 차단"을 분명히. 이번엔 로그인 처리를 Supabase에 맡기므로, 구글 클라이언트 ID·시크릿 발급 → Supabase(Authentication → Providers → Google) 등록까지 Claude에게 부탁하면 차례로 안내해 줍니다. OAuth가 실제로 어떻게 도는지는 덱 3에서 깊게.

SETUP · 데이터 담을 표

시작 전 하나 — 메모 담을 표를 만든다

왜 먼저

메모를 저장하려면 — Supabase에 메모를 담을 표가 있어야 합니다. 데이터 도우미가 이 표에 넣고 꺼냅니다.

  • 표에 담을 것 — 내용 · 작성 시각 · 작성한 사람
  • SQL을 직접 몰라도 됨 — Claude가 만들어 줌
  • 받은 SQL은 Supabase → SQL Editor에 붙여넣기
프롬프트 · 표 만들기 
Supabase에 메모를 저장할 표를 하나 만들어줘.
- 담을 것: 메모 내용, 작성 시각, 작성한 사람
- 로그인한 사람은 자기 메모만 보이게 (다른 사람 메모는 안 보이게)
- 표 만드는 SQL도 같이 알려주고, 어디에 붙여넣는지도 설명해줘

Supabase SQL Editor에서 이 표를 만들어 두면 — 데이터 도우미가 곧바로 메모를 저장·조회할 수 있습니다.

PROMPT · 협업 지휘

도우미 셋에게 — 이 프롬프트 하나로 맡긴다

감독에게 — 통째로 맡긴다

@로 도우미를 하나씩 부를 수도 있지만 — 프로젝트 전체는 메인 Claude에게 통째로 맡기는 게 편합니다. 메인 Claude가 감독이 되어 — 목표·규칙을 읽고, 무엇을 동시에·무엇을 차례로 할지 판단해 셋에게 나눠 줍니다.

  • 한 프롬프트 = 목표 · 진행 방식 · 규칙
  • 순서를 일일이 지정하지 말고 — 감독에게 맡긴다
  • 동시에 될 일은 병렬로 — 감독이 판단
프롬프트 · 감독에게 통째로 
ui-helper · data-helper · login-helper 세 도우미와 "나만의 메모장" 앱을 만들어줘.
네가 감독이 되어 일을 나눠 맡겨줘.

[목표] 로그인하면 — 내 메모를 쓰고·보고·고치고·지우는 앱
[진행] 순서는 네가 정해 — 동시에 되는 건 병렬로, 합치는 건 차례로
[규칙]
· 큰 결정은 나에게 먼저 물어봐
· 키는 환경변수로 — 코드에 직접 쓰지 마
· 단계마다 한 일을 3줄로 알려줘

순서를 하나하나 지정하기보다 — 감독에게 맡기는 게 낫습니다. 동시에 될 일은 병렬로, 합쳐야 할 일만 차례로 — 그 판단을 감독이 합니다. 중간에 큰 결정을 물어오면 답하며 같이 가세요.

MULTI-AGENT · 한 명에서 한 팀으로

도우미 한 명이 아니라 — 한 팀으로.

서브에이전트 하나는 "직원 한 명". 여러 도우미를 동시에·협업시키는 것이 멀티에이전트입니다. 새로운 부품이 아니라 — 서브에이전트를 여러 개 쓰는 "운용 방식"이죠.

정체서브에이전트=부품, 멀티에이전트=여러 개 쓰는 패턴
비유직원 한 명 vs — 팀을 꾸려 분업·협업
