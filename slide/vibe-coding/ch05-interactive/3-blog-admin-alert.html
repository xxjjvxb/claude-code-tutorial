덱 2에서 다른 사람이 글을 남기는 페이지를 만들었습니다. 이번엔 내가 글을 발행하는 블로그, 나만 들어가는 관리자 화면, 그리고 새 글이 올라오면 휴대폰으로 오는 알림까지 — 사이트가 "운영"되기 시작하는 최소 구성을 갖춥니다.

WHY · 운영되는 사이트

방문자가 쓰는 페이지에서 — 내가 운영하는 사이트로.

방명록은 남이 글을 남기고 가는 곳입니다. 여기에 세 가지를 더하면 성격이 완전히 달라집니다 — 내가 발행하는 글, 나만 여는 관리 화면, 그리고 무슨 일이 생기면 바로 오는 알림.

블로그내가 쓴 글이 목록으로 쌓인다
관리자남의 글을 내리고, 내 글을 발행한다
알림새 글이 올라오면 휴대폰으로
CONCEPT · 둘은 다르다

방명록과 블로그 — 누가 쓰느냐가 다르다

방명록 · 덱 2에서 완성
로그인한 누구나 쓴다
짧은 한마디 — 제목이 없다
남긴 순서대로 쌓인다

손님이 남기고 가는 자리.

블로그 · 오늘 추가
나만 쓴다
제목 + 본문 — 길게 쓴다
공개 / 비공개 상태가 있다

내가 발행하는 자리.

그래서 표(테이블)를 따로 만듭니다 — 성격이 다르면 필요한 칸도 다릅니다. 방명록엔 제목이 필요 없고, 블로그엔 "아직 공개 안 함"이 필요하죠.

STEP 1 · 표

블로그 글을 담을 표 만들기

프롬프트 · 블로그 표 
Supabase에 블로그 글을 담을 표를 하나 만들어줘.
제목·본문·작성시각, 그리고 공개/비공개 상태가 필요해.
읽기는 공개된 글만 누구나 볼 수 있고,
쓰기·수정·삭제는 내 계정만 되게 데이터베이스 규칙으로 막아줘.
내 계정 이메일은 <내 구글 이메일> 이야.

방명록 표는 그대로 둡니다 — 새 표를 하나 더 만드는 거예요. "읽기는 누구나, 쓰기는 나만"이 이 표의 핵심 규칙입니다.

STEP 2 · 화면

도우미 둘에게 블로그 화면 맡기기

@designer 에게 
블로그 화면을 만들어줘.
글 목록(제목·날짜)과 글 하나를 펼쳐 보는 화면.
내 홈페이지 분위기 그대로, 폰에서도 읽기 좋게.
저장·권한은 개발자 몫 — 건드리지 않는다.
@developer 에게 
블로그 글을 Supabase에 저장하고 불러온다.
공개된 글만 목록에 보이게 하고, 최신 글이 위로.
글쓰기·수정은 내 계정으로 로그인했을 때만.
키는 환경변수로 둔다.

덱 2에서 만든 designer·developer를 그대로 씁니다 — 도우미는 한 번 만들면 계속 재사용합니다. 새로 만들 필요 없습니다.

ADMIN · 나만의 문

관리자 페이지 — 나만 들어가는 화면

무엇을 하나

  • 방명록에 달린 이상한 글 내리기
  • 블로그 글 발행 / 비공개 전환
  • 지금까지 쌓인 글을 한눈에 보기

왜 따로 두나

  • 손님 화면에 섞이면 실수로 눌립니다
  • 주소를 따로 — /admin
  • 로그인한 내 계정만 통과

관리자 페이지는 거창한 게 아닙니다 — 목록 + 삭제 버튼 + 발행 버튼이면 충분합니다. 처음부터 크게 만들지 마세요.

PRINCIPLE · 오늘의 핵심

버튼을 숨기는 것과 막는 것은 다르다

화면에서 숨기면

  • 관리자 버튼이 안 보일 뿐
  • 주소를 직접 치면 들어와집니다
  • 잠근 게 아니라 가린 것

데이터베이스에서 막으면

  • Supabase가 "이 사람 아니면 거절"
  • 화면을 어떻게 조작해도 통과 못 함
  • 이게 진짜 잠금

그래서 Claude에게 "화면에서 안 보이게"가 아니라 — "내 계정만 쓸 수 있게 데이터베이스 규칙으로 막아줘"라고 말합니다. 이 한 문장 차이가 진짜 잠금과 흉내의 차이입니다.

STEP 3 · 관리자

/admin 화면 붙이기

프롬프트 · 관리자 페이지 
/admin 주소에 관리자 페이지를 만들어줘.
내 계정(<내 구글 이메일>)으로 로그인했을 때만 열리게 하고,
다른 사람이 주소를 직접 쳐도 못 들어가게
데이터베이스 규칙으로도 막아줘.
방명록 글 삭제, 블로그 글 발행/비공개 전환이 되면 돼.

로그인 자체는 4장에서 붙인 구글 로그인을 그대로 씁니다 — 새로 만들 게 없습니다. "누가 들어왔는지"는 이미 알고 있으니, "그게 나인지"만 확인하면 됩니다.

ALERT · 3장 봇 재사용

새 글이 올라오면 — 휴대폰으로

3장과 뭐가 다른가

  • 3장 Stop 훅 — 내 컴퓨터의 Claude가 보냄
  • 이번엔 — 배포된 사이트가 보냄
  • 보내는 쪽만 다르고 받는 곳은 같은 채팅방

그때 만든 것 그대로

  • 봇 — 3장에서 BotFather로 만든 것
  • 토큰과 chat_id — 그때 받은 값
  • 새로 만들 필요 없습니다

3장에서 만든 봇을 버리지 마세요 — 여기서 다시 씁니다. 토큰과 chat_id를 메모해 둔 곳을 지금 열어 두세요.

STEP 4 · 알림

방명록에 글이 달리면 알림 보내기

프롬프트 · 텔레그램 알림 
방명록에 새 글이 등록되면 텔레그램으로 알림이 오게 해줘.
글쓴이 이름과 글 앞부분이 보이면 좋겠어.
봇 토큰과 chat_id는 코드에 직접 쓰지 말고 환경변수로 두고,
배포된 사이트에서도 오도록 Vercel에 같은 환경변수를
넣는 방법까지 알려줘.
토큰은 코드에 적지 않습니다

코드에 적으면 GitHub에 그대로 올라갑니다 — 공개 저장소면 남이 내 봇을 조종할 수 있습니다. 환경변수로 두고, Vercel 대시보드에도 같은 값을 넣어야 배포된 사이트에서 알림이 옵니다.

TROUBLE · 막히면

안 될 때 — 이 네 가지부터

1

알림이 안 온다 → Vercel 환경변수에 토큰·chat_id를 넣었는지. 내 컴퓨터에만 있으면 배포된 사이트는 모릅니다

2

/admin에 아무나 들어와진다 → 화면만 숨긴 상태. "데이터베이스 규칙으로 막아줘"라고 다시 요청

3

블로그 글이 목록에 없다 → 아직 "공개" 상태가 아닌 글. /admin에서 발행으로 바꾸면 나타납니다

4

내 컴퓨터에선 되는데 배포하면 안 된다 → 환경변수, 그리고 구글 로그인 허용 주소(4장)에 배포 주소가 들어갔는지

막히면 증상 그대로 Claude에게 말하세요 — "배포한 사이트에서만 알림이 안 와요"처럼. 어디를 봐야 하는지 알려줍니다.
