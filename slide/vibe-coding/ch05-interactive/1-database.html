껐다 켜면 사라진다 — 데이터는 어딘가 담겨야.

방명록에 글을 남겼는데 새로고침하면 사라진다면 — 그건 방명록이 아니죠. 남긴 글이 계속 남아 있어야 합니다. 데이터를 차곡차곡 담아두는 전용 창고가 데이터베이스입니다.

CRUD · 데이터로 하는 4가지

데이터로 하는 일은 — 결국 이 4가지

C · Create

추가

새 메모를 표에 한 줄 더한다.

R · Read

조회

저장된 메모를 불러와 화면에 보여준다.

U · Update

수정

이미 있는 메모의 내용을 고친다.

D · Delete

삭제

필요 없어진 메모를 지운다.

CRUD — 추가·조회·수정·삭제. 방명록이든 쇼핑몰이든, 데이터를 다루는 앱은 모두 이 네 가지의 조합입니다.

TYPES · 두 갈래

데이터베이스엔 — SQL과 NoSQL 두 갈래

SQL — 표 방식

정해진 표에 줄을 세운다

  • 행·열이 정해진 표 — 엑셀처럼 정돈됨
  • 규칙이 엄격해 데이터가 흐트러지지 않음
  • 표끼리 연결도 가능 (회원 ↔ 메모)
  • 예: PostgreSQL, MySQL
NoSQL — 문서 방식

자유로운 묶음으로 담는다

  • 표 틀이 없어 — 형태가 제각각이어도 OK
  • 유연하지만 — 정돈은 내가 챙겨야
  • 예: MongoDB, Firebase Firestore

정답은 없지만 — 데이터를 처음 다뤄본다면 표가 눈에 보이는 SQL이 직관적입니다. 그래서 오늘은 SQL로.

CHOICE · 오늘의 데이터베이스

우리의 선택 — Supabase

왜 Supabase

  • 무료 — 수업·개인 프로젝트엔 무료 티어로 충분
  • SQL — 표가 스프레드시트처럼 눈에 보임
  • 백엔드 서버를 따로 안 만들어도 됨 (BaaS)

내 앱이 Supabase에 바로 연결 — 서버 코드 없이.

Supabase가 해주는 3가지

  • 데이터베이스 — 메모를 담는 표
  • CRUD 연결 — 추가·조회·수정·삭제 통로
  • 로그인 — 구글 로그인까지 내장

방명록에 필요한 게 — 도구 하나에 다 들어 있음.

"백엔드"는 보통 따로 만들어 띄우는 서버지만 — Supabase 같은 서비스(BaaS)를 쓰면 그 서버 없이 앱이 바로 데이터에 연결됩니다.
