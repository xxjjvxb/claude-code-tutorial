자기소개 페이지를 세상에 공개

앞 덱에서 만든 자기소개 페이지는 아직 내 컴퓨터 안에만 있습니다. GitHub와 Vercel로 인터넷에 올려, 링크 하나로 누구에게나 공유합니다 — 전부 무료.

CONCEPT · 서버가 뭐길래

내 화면의 페이지 — 남에겐 왜 안 보일까

서버

"페이지 주세요" 요청이 오면 파일을 내어주는, 늘 켜져 있는 컴퓨터. 모든 웹사이트 뒤에는 서버가 있습니다.

localhost

"내 컴퓨터 자신"을 부르는 주소(127.0.0.1). 그래서 localhost 주소는 오직 내 컴퓨터에서만 통합니다.

포트(:3000)

한 컴퓨터에 있는 여러 창구의 번호. localhost:3000 = 내 컴퓨터의 3000번 창구.

흔한 사고 — localhost:3000 링크를 친구에게 보내면, 친구는 자기 컴퓨터의 3000번을 열게 됩니다. 당연히 아무것도 없죠. 내 페이지를 세상에 보이려면 인터넷에 늘 켜져 있는 서버에 올려야 합니다.

WHY · 왜 Vercel인가

서버를 직접 차리는 대신 — 빌려 쓴다

24시간 켜 둬야 함 — 끄면 사이트도 꺼짐
고정 주소·도메인 직접 마련
보안·트래픽 폭주 다 내 책임
전기세·소음은 덤
○ Vercel에 맡기면
파일만 올리면 — 전 세계에서 접속되는 주소 발급
24시간 무중단 · 서버 관리 0
push하면 자동 반영 (배포 파이프라인)
개인·학습용은 무료

Vercel 같은 서비스를 "호스팅"이라 부릅니다 — 서버 운영을 통째로 대신해주는 것. 우리는 만들기에만 집중하고, 서버는 빌려 씁니다.

WHY · 왜 배포하나

내 컴퓨터 속 파일 → 전 세계 누구나

지금까지는

  • index.html은 내 컴퓨터에만 존재
  • 남에게 보여주려면 파일을 직접 전달해야 함
  • 휴대폰·다른 PC에서는 열 수 없음

배포하면

  • 인터넷 주소가 생김 — 내이름.vercel.app
  • 링크만 보내면 누구나 접속
  • 휴대폰에서도 똑같이 열림

Vercel은 HTML·CSS 같은 정적 사이트를 무료로 호스팅합니다. GitHub에 코드를 올려두면 Vercel이 자동으로 가져가 배포합니다.

STEP 1 · GitHub 저장소

자기소개 폴더를 저장소로

GitHub에서 — 새 저장소

  1. github.com 우측 상단 + → New repository
  2. 이름 입력 (예: my-intro) — 영문·하이픈
  3. Public 선택 → Create repository
  4. 다음 화면의 주소(...git)를 복사해 둠
PowerShellTerminal 
git init
git add .
git commit -m "자기소개 페이지"

앞 덱(Git 기초)에서 이미 커밋했다면 오른쪽 3줄은 건너뛰어도 됩니다. 저장소(repository) = GitHub에 올린 프로젝트 폴더 한 칸 — 자기소개 페이지 전용으로 하나 만듭니다.

SCREEN · 새 저장소 만들기

GitHub — New repository 화면

이 화면에서 확인할 것

  • Repository name만 채우면 됩니다 — 나머지는 기본값
  • 공개 범위는 Public (무료로 누구나 볼 수 있음)
  • Add a README·.gitignore 체크박스는 모두 비워둠

초록색 Create repository를 누르면 나오는 ...git 주소를 다음 STEP에서 붙여넣습니다.

README를 함께 만들면 첫 push에서 충돌이 날 수 있어요 — 지금은 빈 저장소로 만드는 게 편합니다.

STEP 2 · push

내 코드를 GitHub로 올리기

push가 하는 일

  • 지금까지 commit은 내 컴퓨터 안 저장
  • push = 그 커밋을 GitHub(원격)으로
  • 한 번 연결하면 다음부턴 git push만
PowerShellTerminal 
git remote add origin [GitHub에서 복사한 주소]
git branch -M main
git push -u origin main

origin 뒤에는 GitHub 저장소 화면에서 복사한 주소(...git)를 붙여넣습니다. 처음 push할 때 GitHub 로그인 창이 뜨면 브라우저에서 승인하면 끝 — 막히면 Claude에게 에러를 그대로 붙여넣어 물어보세요.

STEP 3 · Vercel ↔ GitHub 연동

Vercel에 GitHub 계정으로 로그인

왜 GitHub로 로그인하나

Vercel이 내 GitHub 저장소를 들여다볼 수 있어야 코드를 가져가 배포합니다. 그래서 새 회원가입 대신 GitHub 계정을 그대로 연결(연동)합니다.

  • 계정 하나로 두 서비스가 연결됨
  • 내가 push하면 → Vercel이 자동 감지 → 재배포
  • 새 아이디·비밀번호 만들 필요 없음

연동 3단계

  1. vercel.com → Sign Up
  2. "Continue with GitHub" 클릭
  3. GitHub 권한 화면 → Authorize Vercel (최초 1회)

"Authorize"는 Vercel이 내 저장소를 읽고 배포하도록 허락하는 것 — 코드를 가져가 웹에 올리는 용도라 안전합니다.

이미 브라우저에 GitHub 로그인이 돼 있으면 클릭 몇 번으로 끝. 한 번 연동하면 다음부턴 다시 묻지 않습니다.

STEP 4 · 저장소 Import

GitHub 저장소를 Vercel로 가져오기

Import = "가져오기"

아까 GitHub에 올린 저장소를 Vercel 프로젝트로 연결해 가져오는 단계입니다.

  1. Add New → Project
  2. 내 저장소 목록에서 my-intro → Import
  3. 설정 화면 그대로 → Deploy

설정은 건드릴 게 없다

  • Framework Preset — Vercel이 자동 감지 (HTML은 "Other"), 그대로 둠
  • Build·Output 칸 — 자기소개 HTML은 빈칸 그대로
  • Deploy → 30초~1분 빌드 → 완료 화면

저장소가 목록에 안 보이면 → "Adjust GitHub App Permissions"에서 접근을 허용해 주세요.

한 번 Import 해두면 이 저장소는 Vercel과 계속 연결 — 이후엔 git push만으로 자동 재배포됩니다.

SCREEN · Import → 배포 → 공개

Vercel — Import 한 번에 배포까지

Deploy 한 번이면 30초~1분 빌드 → Congratulations → 발급된 주소로 접속까지 자동입니다.

STEP 5 · 도메인 공유

내이름.vercel.app
— 내 페이지 주소

배포가 끝나면 Vercel이 인터넷 주소를 발급합니다. 이 링크를 가진 사람은 누구나, 어디서나 내 자기소개 페이지를 볼 수 있습니다.

확인Vercel 화면의 Visit 버튼 → 내 페이지 열림
공유주소를 복사해 강사가 안내한 채널에
테스트휴대폰으로 열어보기 — PC와 똑같이 보임
STEP 6 · 수정과 재배포

고치고 git push — 자동으로 갱신

PowerShellTerminal (zsh) — 페이지 수정 후
# 자기소개 페이지를 고쳤다면 git add . git commit -m "사진 추가" git push Vercel이 push를 자동 감지 → 재배포 ✓ 같은 주소에 최신 내용 반영

한 번 연결해두면 — 같은 주소가 항상 최신입니다. git push 한 줄이면 몇 초 뒤 반영, 별도 업로드 작업이 없습니다.
