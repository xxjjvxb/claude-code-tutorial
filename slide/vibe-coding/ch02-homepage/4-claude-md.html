TOPIC 01 · WHY · CLAUDE.md

매 세션 자동 주입되는 룰북.

프로젝트 루트에 두는 마크다운 파일. 그 폴더에서 claude를 켤 때마다 첫 컨텍스트로 자동 들어갑니다 — 매번 설명할 필요 X.

자동매 세션 시작 시 컨텍스트에 포함
절약"한국어로 답해줘" 매번 안 해도 됨
팀git에 올려서 모두가 같은 룰
GOOD vs BAD · 양 끝

CLAUDE.md — 짧고 명확하게

× 나쁜 예 (장황한 200줄+)
# 프로젝트 소개
이 프로젝트는 ... (300자 설명)
# 코딩 스타일 (50줄)
# 의존성 (40줄)
# 폴더 설명 (30줄)
...

300줄 → 매 요청마다 토큰 ↑ + 정작 중요한 게 묻힘.

✓ 좋은 예 (30줄 이내)
# 답변 규칙
- 한국어로 답해줘
# 기술 스택
- Flask 3.0 · Python 3.11
# 룰
- 새 라우트는 routes/에 분리
- 테스트는 tests/에 pytest

30줄 → 토큰 부담 없음 + 핵심이 또렷.

RULE · 200줄 한도

CLAUDE.md는 200줄 이하 유지.

200줄 넘기 시작하면 핵심이 군더더기에 묻힙니다. 매 세션 자동 주입이라 길이가 곧 비용 ↑.

초보10–30줄 — 답변 규칙 + 핵심 스택만
중급50–100줄 — 폴더 룰 + 테스트 패턴 추가
상한200줄 — 넘으면 분리 또는 다이어트
HIERARCHY · 3단 계층

CLAUDE.md는 3개 위치에 둘 수 있다

프로젝트

./CLAUDE.md

현재 작업 폴더 안. 그 프로젝트만의 규칙. 가장 자주 쓰는 위치.

유저

~/.claude/CLAUDE.md

홈 폴더. 모든 프로젝트에 자동 적용. "한국어로 답해줘" 같은 본인 공통 규칙.

엔터프라이즈

/etc/claude/CLAUDE.md

시스템 전체 (관리자 설정). 회사·강의실 공통 규칙. 이 강의에선 사용 X.

3개가 모두 있으면 모두 합쳐서 컨텍스트에 들어감 — 충돌 없으면 자연스럽게 결합. 여기까지가 "룰북". 다음은 매 요청에서 AI가 더 잘 생각하게 만드는 법입니다.

TOPIC 02 · 더 깊이 생각하게

막힐 땐 — Claude가 더 깊이 생각하게

/effort — 사고 강도를 단계로

  • /effort 입력 → 화살표로 강도 슬라이더 조절
  • /effort xhigh처럼 단계를 바로 지정도 가능
  • 높일수록 깊게 생각 — 대신 느리고 비쌈
  • 한 번 정하면 그 세션 내내 적용

ultrathink — 이번 한 번만 최대로

  • 프롬프트에 ultrathink 한 단어를 섞어 쓰기
  • 특수 문법 X — 평문에 그대로 넣으면 인식
  • 그 요청 한 번만 — 최대 강도로 생각
  • 막힌 디버깅 · 어려운 결정 앞에서

평소엔 그냥 시키세요 — 막히는 문제에서만 /effort를 올리거나 ultrathink. 깊게 생각할수록 느리고 비싸집니다.

USAGE · 막힐 때만

평소엔 그냥 — 막힐 때 ultrathink 한 단어

평소 — 그냥
"왜 테스트가 깨지는지 디버깅해줘"
...
바로 답 → 단순 문제엔 충분

대부분은 이걸로 충분합니다.

막힐 때 — ultrathink 추가
"ultrathink 왜 테스트가 깨지는지 디버깅해줘"
...
여러 가설 검토 → 더 정확

막혀 있을 때 — 느리지만 답이 옵니다.

특수 문법 아님 — 평문에 ultrathink 한 단어. 세션 내내 깊게 보려면 /effort로 강도 자체를 올려도 됩니다.

META · 프롬프트도 AI에게

"먼저 어떻게 시킬지 계획부터"

앞 덱에서 본 메타 프롬프트의 확장 — 막힌 작업 앞에서 Claude에게 "이걸 어떻게 시켜야 잘 될까"부터 물어봅니다.

예시 1"이 작업 잘 진행하려면 어떤 프롬프트가 좋을까?"
예시 2"이걸 작은 단위로 자르면 몇 단계?"
예시 3"내가 모르는 게 뭐야? 빠진 정보 알려줘"
SELF-CHECK · 자기 검증 요구

결과 받은 뒤 — "스스로 검증해봐"

× 받자마자 다음으로
"코드 작성됨"
"OK 다음"
...실제로 동작 안 함 발견
한참 뒤 디버깅 시작

검증 없이 진행 → 사고 누적.

✓ 검증 요구
"코드 작성됨"
"이 코드가 실제로 동작할지
한 번 더 검토해봐. 빠진 게 있어?"

TOPIC 03 · .claude 폴더 구조

프로젝트 안 .claude 폴더가 모든 설정의 중심.

이 장 뒤에서 배울 Hooks 설정(settings.json)도 여기 들어갑니다. 강의가 진행되며 이 폴더에 파일이 하나씩 추가됩니다.

생성/init 또는 git clone 시 자동 생성
git팀과 공유 — git에 같이 commit
크기처음엔 빈 폴더 — 필요할 때마다 추가
ROLES · 각 폴더 역할

5개 폴더·파일 — 장별 등장

CLAUDE.md (이 덱 ★)

프로젝트 룰북. 매 세션 자동 주입. 200줄 이하 권장.

settings.json (2장)

Hook 정의 + 권한 설정. 이 장에서 만들 Telegram 알림이 여기.

commands/ (다음 덱)

커스텀 슬래시 — /myslash 같은 본인 명령. 마크다운 한 파일씩.

agents/ (5장)

Sub-agent 정의 — 테스트 작성 전담 등 역할별 분리. 마크다운 한 파일씩.

hooks/ (2장)

Hook 스크립트 — settings.json에서 호출하는 .ps1 등.

skills/ (7장)

공식 Skill (PPTX·DOCX 등) 또는 커스텀. anthropic/skills 참고.

장이 지날 때마다 하나씩 추가 — 강의 끝엔 본인만의 .claude/ 폴더가 생겨 있을 겁니다.

TOPIC 04 · PRINCIPLE · 길이가 아니라 핵심

CLAUDE.md는 핵심만 남기고
군더더기는 빼라.

매 세션 자동 주입 = 매 요청 토큰. 길이가 곧 비용. 짧고 정확한 30줄이 장황한 300줄보다 항상 잘 작동합니다.

핵심Claude가 모르면 큰 사고가 날 정보 (스택·룰)
군더더기코드 보면 알 수 있는 것 (변수명·구조)
결과30줄짜리 CLAUDE.md가 300줄짜리보다 더 잘 작동
PRACTICAL · 무엇을 적을까

핵심만 적기 — 5가지 카테고리

1. 답변 규칙

  • 한국어로 답해줘
  • 코드 블록은 마크다운으로

CASE · Karpathy의 CLAUDE.md

좋은 CLAUDE.md엔 — 코드가 아니라 '일하는 방식'

1 · Think Before Coding

짜기 전에 생각 — 가정하지 말고, 모르면 묻기

2 · Simplicity First

단순함 먼저 — 문제를 푸는 최소한의 코드만

3 · Surgical Changes

외과수술 같은 변경 — 꼭 필요한 곳만

4 · Goal-Driven Execution

목표 기반 실행 — 성공 기준을 정하고 검증

스택·명령어 같은 '정보'가 아니라 — 어떻게 일할지라는 판단 기준 4가지가 담겨 있습니다. 이런 생각을 md에 녹이면, 매 세션 Claude가 그 방식으로 움직입니다 — 하나씩 뜯어봅니다.

PRINCIPLE · 1 — 2

짜기 전에 생각 · 단순함을 먼저

1 · Think Before Coding

"Don't assume. Don't hide confusion. Surface tradeoffs."

  • 가정은 드러내 말한다 — 불확실하면 묻는다
  • 해석이 여러 갈래면 — 말없이 고르지 말고 펼쳐 보인다
  • 더 단순한 길이 보이면 말한다 — 필요하면 반박한다
  • 막히면 멈추고 — 무엇이 헷갈리는지 짚고 묻는다

2 · Simplicity First

"Minimum code that solves the problem. Nothing speculative."

  • 요청한 것 이상은 만들지 않는다
  • 한 번 쓸 코드에 추상화는 없다
  • 200줄로 짠 게 50줄이면 — 다시 쓴다
  • "선임이 보면 과하다 할까?" — 그렇다면 단순화

영문은 Karpathy의 원문 그대로, 한글은 그 뜻 — 규칙이 아니라 일하는 태도를 적었다는 점에 주목하세요.

PRINCIPLE · 3 — 4

꼭 필요한 곳만 — 그리고 검증될 때까지

3 · Surgical Changes
