CONCEPT · 환경변수 · PATH

환경변수 — 시스템이 공유하는 설정값

PATH가 뭔가

"명령어를 어디서 찾을지" 폴더 목록을 적어둔 환경변수.

  • PowerShell셸(zsh)이 claude를 PATH 폴더들에서 검색
  • 설치 스크립트가 PATH에 자동 추가
  • 새로 등록된 PATH는 새 터미널에서만 적용 — 방금 설치한 claude를 새 터미널에서 확인하는 이유
PATH (시스템 환경변수) ├── C:\Windows\System32 ├── C:\Users\you\.claude\bin\ ← claude.cmd └── ... PS> claude → 위 폴더들에서 검색 → 실행
$PATH (환경변수) ├── /usr/local/bin ├── /usr/bin ├── ~/.claude/bin/ ← claude └── ... $ claude → 위 폴더들에서 검색 → 실행

"인식되지 않습니다command not found"는 99% PATH 문제. 새 터미널이 1차 해결책 — 곧 설치할 Orca의 터미널이 바로 그 새 터미널입니다.

필수 · Node.js · 홈페이지 배포 준비

Node.js — 지금 설치해 둡니다

받는 곳
nodejs.org ↗
  1. nodejs.org 접속 → "LTS" 큰 버튼 클릭 (Windows .msi 자동 다운로드)
  2. node-v22.x.x-x64.msi(LTS 버전 숫자는 다를 수 있음) 더블클릭 → 보안 경고 "예" → 설치 마법사 Next 따라 진행
  3. Custom Setup에서 "Add to PATH" 체크 확인 → Install → UAC 승인 → 1~2분 대기
  4. 완료 후 새 내장 터미널에서 node --version → v22.x.x 처럼 버전 숫자가 나오면 OK
받는 곳
Homebrew · nodejs.org ↗
  1. Homebrew가 설치돼 있으면 brew install node 한 줄 — 30초~1분
  2. Brew가 없으면 nodejs.org → "LTS" 버튼 → .pkg 다운로드 → 더블클릭 → 설치 마법사
  3. 설치 후 새 내장 터미널에서 node --version → v22.x.x 처럼 버전 숫자가 나오면 OK
  4. Homebrew 자체 설치는 /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

왜 필요? 홈페이지를 만들고 배포할 때 쓰는 웹 도구들(로컬 미리보기 서버·배포 도구)이 Node.js 위에서 돌아갑니다 — 2장 배포까지 가려면 필수.

선택 · TROUBLESHOOTING · 자주 막히는 5가지

막혔을 때 먼저 시도할 것들

01
"인식되지 않습니다command not found"
내장 터미널 새로 열기 → PATH 갱신. 안 되면 Orca 재시작. 독립 PowerShell(시작 메뉴 검색)터미널(Spotlight)로도 확인 가능.
02
PowerShell 스크립트 실행 정책 에러
관리자 PowerShell → Set-ExecutionPolicy -Scope CurrentUser RemoteSigned → 재시도.
02
"Permission denied" / 실행 권한 에러
설치 스크립트를 다시 실행하거나, 막힌 파일에 chmod +x ~/.claude/bin/claude. Mac은 별도 정책 없음 — 권한만 맞으면 OK.
03
claude 실행 시 로그인·인증 에러
claude 안에서 /login → 브라우저에서 본인 Claude 계정으로 다시 로그인. 계속 안 되면 오른쪽 질문 버튼에.
04
로그인 브라우저가 안 열림
터미널에 표시되는 URL을 직접 복사해서 브라우저에 붙여넣기.
05
Orca가 안 열리거나 이상하게 동작
완전히 종료 후 다시 실행 → 그래도 안 되면 onorca.dev에서 최신 버전 재설치.
