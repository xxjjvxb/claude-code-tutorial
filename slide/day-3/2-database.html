데이터베이스 — 데이터를 담아두는 그릇

지금까지 만든 페이지는 껐다 켜면 입력한 게 사라집니다. 진짜 서비스는 데이터를 어딘가에 저장해야 합니다. 데이터베이스가 무엇이고, CRUD가 무엇인지 — 그리고 다음 챕터의 메모장에 쓸 Supabase를 준비합니다.

WHY · 왜 필요한가

껐다 켜면 — 입력한 게 사라진다.

메모를 적고 새로고침하면 사라집니다. 다음 챕터에서 만들 "나만의 메모장"이 진짜 메모장이 되려면 — 적은 내용이 어딘가에 남아 있어야 합니다. 그 "어딘가"가 데이터베이스입니다.

화면보여줄 뿐 — 닫으면 사라진다
저장데이터가 남아야 — 내일 다시 봐도 그대로
공유저장돼 있어야 — 다른 기기·다른 사람도
WHAT · 데이터베이스

데이터베이스 — 정리된 데이터 창고

한 줄로

데이터를 차곡차곡 담아두고, 필요할 때 꺼내 쓰는 전용 창고.

  • 메모·회원·주문… 무엇이든 담는다
  • "엑셀의 똑똑한 버전" — 정리·검색이 빠름
  • 여러 사람이 동시에 써도 안전하게

앱과의 관계

화면(앱)은 보여주고 입력받는 곳, 데이터베이스는 실제로 담아두는 곳.

  • 메모를 쓰면 → 데이터베이스에 저장
  • 앱을 열면 → 데이터베이스에서 불러옴
  • 둘은 항상 짝 — 화면 + 창고

우리가 데이터베이스 코드를 직접 쓰지 않습니다 — "메모를 저장해줘"라고 하면 Claude가 알아서 다룹니다.

TABLE · 표로 들여다보기

데이터는 — 표(table)에 줄줄이 쌓인다

엑셀처럼 — 행과 열

  • 열(column) — 어떤 항목인지 (내용·작성일…)
  • 행(row) — 메모 하나하나
  • 메모를 추가하면 — 표에 행이 하나 늘어남

"메모가 표의 한 줄이 된다" — 눈에 보이는 그대로.

Supabase에는 이 표를 스프레드시트처럼 보여주는 화면이 있어 — 데이터가 쌓이는 게 눈에 보입니다.

CRUD · 데이터로 하는 4가지

데이터로 하는 일은 — 결국 이 4가지

C · Create

추가

새 메모를 표에 한 줄 더한다.

R · Read

조회

저장된 메모를 불러와 화면에 보여준다.

U · Update

수정

이미 있는 메모의 내용을 고친다.

D · Delete

삭제

필요 없어진 메모를 지운다.

CRUD — 추가·조회·수정·삭제. 메모장이든 쇼핑몰이든, 데이터를 다루는 앱은 모두 이 네 가지의 조합입니다.

TYPES · 두 갈래

데이터베이스엔 — SQL과 NoSQL 두 갈래

SQL — 표 방식

정해진 표에 줄을 세운다

  • 행·열이 정해진 표 — 엑셀처럼 정돈됨
  • 규칙이 엄격해 데이터가 흐트러지지 않음
  • 표끼리 연결도 가능 (회원 ↔ 메모)
  • 예: PostgreSQL, MySQL
NoSQL — 문서 방식

자유로운 묶음으로 담는다

  • 표 틀이 없어 — 형태가 제각각이어도 OK
  • 유연하지만 — 정돈은 내가 챙겨야
  • 예: MongoDB, Firebase Firestore

정답은 없지만 — 데이터를 처음 다뤄본다면 표가 눈에 보이는 SQL이 직관적입니다. 그래서 오늘은 SQL로.

CHOICE · 오늘의 선택

이번엔 — Supabase를 씁니다.

Supabase는 무료로 쓸 수 있는 SQL 데이터베이스 서비스입니다. 표가 스프레드시트처럼 보이고, 백엔드 서버를 따로 만들 필요가 없어 — 비개발자가 데이터를 처음 다뤄보기에 가장 좋습니다.

무료수업·개인 프로젝트엔 무료 티어로 충분
보인다표 편집기 — 데이터가 쌓이는 게 눈에
백엔드 X서버를 안 만들어도 됨 — 다음 장에서 설명
HOW · Supabase가 해주는 일

Supabase 하나면 — 서버 없이 3가지가 끝

①

데이터베이스

메모를 담는 표. 표 편집기로 직접 들여다봄.

②

CRUD 연결

앱이 데이터를 추가·조회·수정·삭제하는 통로를 자동 제공.

③

로그인

구글 로그인까지 내장 — 다음 챕터 메모장에 그대로.

백엔드 서버를 따로 안 만들어도 됩니다 — 내 앱이 Supabase에 바로 연결됩니다. (Firebase도 같은 방식 — 서버가 필요 없는 서비스입니다.)
