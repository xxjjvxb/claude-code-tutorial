TOPIC 01 · WHY · CLAUDE.md

매 세션 자동 주입되는 룰북.

프로젝트 루트에 두는 마크다운 파일. 그 폴더에서 claude를 켤 때마다 첫 컨텍스트로 자동 들어갑니다 — 매번 설명할 필요 X.

자동매 세션 시작 시 컨텍스트에 포함
절약"한국어로 답해줘" 매번 안 해도 됨
팀git에 올려서 모두가 같은 룰
GOOD vs BAD · 양 끝

CLAUDE.md — 짧고 명확하게

× 나쁜 예 (장황한 200줄+)
# 프로젝트 소개
이 프로젝트는 ... (300자 설명)
# 코딩 스타일 (50줄)
# 의존성 (40줄)
# 폴더 설명 (30줄)
...

300줄 → 매 요청마다 토큰 ↑ + 핵심 신호 묻힘.

✓ 좋은 예 (30줄 이내)
# 답변 규칙

- Flask 3.0 · Python 3.11

- 테스트는 tests/에 pytest

30줄 → 토큰 부담 없음 + 신호 명확.

RULE · 200줄 한도

CLAUDE.md는 200줄 이하 유지.

200줄 넘기 시작하면 신호대잡음비가 무너집니다. 매 세션 자동 주입이라 길이가 곧 비용 ↑.

초보10–30줄 — 답변 규칙 + 핵심 스택만
중급50–100줄 — 폴더 룰 + 테스트 패턴 추가
상한200줄 — 넘으면 분리 또는 다이어트
HIERARCHY · 3단 계층

CLAUDE.md는 3개 위치에 둘 수 있다

프로젝트

./CLAUDE.md

현재 작업 폴더 안. 그 프로젝트만의 규칙. 가장 자주 쓰는 위치.

유저

~/.claude/CLAUDE.md

홈 폴더. 모든 프로젝트에 자동 적용. "한국어로 답해줘" 같은 본인 공통 규칙.

엔터프라이즈

/etc/claude/CLAUDE.md

시스템 전체 (관리자 설정). 회사·강의실 공통 규칙. 5일 강의에선 사용 X.

3개가 모두 있으면 모두 합쳐서 컨텍스트에 들어감 — 충돌 없으면 자연스럽게 결합.

TOPIC 02 · CoT · think 단계

"생각하라"고 시키면 더 잘함 — Chain of Thought

think

기본 — 짧은 추론

  • 토큰 +500
  • 응답 시간 +5초
  • 일반 질문에

think hard

조금 더 깊게

  • 토큰 +2K
  • 응답 시간 +15초
  • 설계 결정에

think harder

더 깊게

  • 토큰 +5K
  • 응답 시간 +30초
  • 복잡 설계 · 디버깅

ultrathink

최대 — 비싸지만 효과

  • 토큰 +10K+
  • 응답 시간 +60초
  • 막힌 디버깅에

평소엔 그냥 시키고, 막히면 think hard, 정말 막히면 ultrathink. 매번 ultrathink하면 비용 폭주.

USAGE · think 단어 넣기

프롬프트에 think를 끼워 넣는다

기본 (think 없음)
"왜 테스트가 깨지는지 디버깅해줘"
...
첫 추측 답변 → 종종 맞춤

단순 문제엔 충분.

think hard 추가
"think hard 왜 테스트가 깨지는지 디버깅해줘"
...
여러 가설 검토 → 더 정확

막혀 있을 때 — 시간·토큰 더 들지만 답이 옴.

특수 문법은 X — 그냥 평문에 단어로 넣기. think, think hard, ultrathink 모두 인식됩니다.

META · 프롬프트도 AI에게

"먼저 어떻게 시킬지 계획부터"

Day 1에 봤던 메타 프롬프트의 확장 — 막힌 작업 앞에서 Claude에게 "이걸 어떻게 시켜야 잘 될까"부터 물어봅니다.

예시 1"이 작업 잘 진행하려면 어떤 프롬프트가 좋을까?"
예시 2"이걸 작은 단위로 자르면 몇 단계?"
예시 3"내가 모르는 게 뭐야? 빠진 정보 알려줘"
SELF-CHECK · 자기 검증 요구

결과 받은 뒤 — "스스로 검증해봐"

× 받자마자 다음으로
"코드 작성됨"
"OK 다음"
...실제로 동작 안 함 발견
한참 뒤 디버깅 시작

검증 없이 진행 → 사고 누적.

✓ 검증 요구
"코드 작성됨"
"이 코드가 실제로 동작할지
한 번 더 검토해봐. 빠진 게 있어?"
→ "import 빠짐" 자가 발견

한 번 더 묻기 = 토큰 1.5배지만 사고 ↓.

자주 쓰는 한 줄: "이거 잘못된 점 있나? 한 번 더 봐줘." 막힌 디버깅 풀리는 경우 의외로 많음.

TOPIC 03 · .claude 폴더 구조

프로젝트 안 .claude 폴더가 모든 설정의 중심.

Hooks 만들 때 본 settings.json도 여기 안에 있었습니다. 5일 동안 이 폴더에 파일이 하나씩 추가됩니다.

생성/init 또는 git clone 시 자동 생성
git팀과 공유 — git에 같이 commit
크기처음엔 빈 폴더 — 필요할 때마다 추가
ROLES · 각 폴더 역할

5개 폴더·파일 — Day 별 등장

CLAUDE.md (Day 3 ★)

프로젝트 룰북. 매 세션 자동 주입. 200줄 이하 권장.

settings.json (Day 3)

Hook 정의 + 권한 설정. 오전에 만든 Telegram 알림이 여기.

commands/ (Day 4)

커스텀 슬래시 — /myslash 같은 본인 명령. 마크다운 한 파일씩.

agents/ (Day 4)

Sub-agent 정의 — 테스트 작성 전담 등 역할별 분리. 마크다운 한 파일씩.

hooks/ (Day 4 +)

Hook 스크립트 — settings.json에서 호출하는 .ps1 등.

skills/ (Day 4)

공식 Skill (PPTX·DOCX 등) 또는 커스텀. anthropic/skills 참고.

하루에 1~2개씩 추가 — 5일 끝엔 본인의 프로덕션급 .claude/ 폴더가 생겨 있을 겁니다.

TOPIC 04 · PRINCIPLE · 길이가 아니라 신호

CLAUDE.md는 신호만 남기고
잡음은 빼라.

매 세션 자동 주입 = 매 요청 토큰. 길이가 곧 비용. 짧고 정확한 30줄이 장황한 300줄보다 항상 잘 작동합니다.

신호Claude가 모르면 큰 사고가 날 정보 (스택·룰)
잡음코드 보면 알 수 있는 것 (변수명·구조)
결과30줄짜리 CLAUDE.md가 300줄짜리보다 더 잘 작동
PRACTICAL · 무엇을 적을까

신호로 적기 — 5가지 카테고리

1. 답변 규칙

  • 한국어로 답해줘
  • 코드 블록은 마크다운으로

2. 기술 스택

  • Python 3.11 · Flask 3.0
  • pytest · pyenv

3. 폴더 룰

  • 새 라우트는 routes/에
  • 테스트는 tests/에

4. 코드 스타일

  • 들여쓰기 4칸
  • 변수명 snake_case

5. 도구·명령

  • python app.py로 실행
  • 테스트: pytest tests/

금지 항목 ✗

  • 코드 보면 알 수 있는 것
  • 장황한 프로젝트 소개
  • 변경 잦은 정보

각 카테고리는 3~5줄이 한도. 5×4 = 20줄이 권장 사이즈.

ANTI-PATTERNS · 흔한 실수

이런 건 CLAUDE.md에 적지 마

⚠ 자주 변하는 것

현재 진행 중 작업

"오늘 라우트 추가하는 중" — 30분 뒤 stale. 별도 메모지에.

⚠ 코드와 중복

함수 시그니처 일일이

"login() 함수는 username, password 받아..." — 코드 보면 됨.

⚠ 너무 일반적

"좋은 코드 짜줘"

의미 없는 지시. Claude는 항상 좋은 코드 짜려고 함 — 구체 룰만.

의심되면 한 번 빼보고 — 빼도 작업이 잘 되면 그건 잡음이었던 것. 다이어트가 답.

TOOLS · 작성 도구

CLAUDE.md 만질 때 3가지 도구

/init

자동 초안

/memory

현재 보기

#

한 줄 추가

대화 중 # 한국어로 → 자동으로 CLAUDE.md에 추가. Day 2에서 한 그것.

새 프로젝트엔 /init부터. 진행하면서 #로 한 줄씩 추가. 가끔 /memory로 한 번 정리.
