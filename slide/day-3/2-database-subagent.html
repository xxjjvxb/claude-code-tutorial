DATABASE · 데이터 창고

껐다 켜면 사라진다 — 데이터는 어딘가 담겨야.

메모를 적고 새로고침하면 사라집니다. 메모장이 진짜가 되려면 — 적은 내용이 남아 있어야 하죠. 데이터를 차곡차곡 담아두는 전용 창고가 데이터베이스입니다.

화면보여줄 뿐 — 닫으면 사라진다
창고데이터베이스에 담으면 — 내일도 그대로
표엑셀처럼 — 행·열의 표에 줄줄이 쌓인다
CRUD · 데이터로 하는 4가지

데이터로 하는 일은 — 결국 이 4가지

C · Create

추가

새 메모를 표에 한 줄 더한다.

R · Read

조회

저장된 메모를 불러와 화면에 보여준다.

U · Update

수정

이미 있는 메모의 내용을 고친다.

D · Delete

삭제

필요 없어진 메모를 지운다.

CRUD — 추가·조회·수정·삭제. 메모장이든 쇼핑몰이든, 데이터를 다루는 앱은 모두 이 네 가지의 조합입니다.

TYPES · 두 갈래

데이터베이스엔 — SQL과 NoSQL 두 갈래

SQL — 표 방식

정해진 표에 줄을 세운다

  • 행·열이 정해진 표 — 엑셀처럼 정돈됨
  • 규칙이 엄격해 데이터가 흐트러지지 않음
  • 표끼리 연결도 가능 (회원 ↔ 메모)
  • 예: PostgreSQL, MySQL
NoSQL — 문서 방식

자유로운 묶음으로 담는다

  • 표 틀이 없어 — 형태가 제각각이어도 OK
  • 유연하지만 — 정돈은 내가 챙겨야
  • 예: MongoDB, Firebase Firestore

정답은 없지만 — 데이터를 처음 다뤄본다면 표가 눈에 보이는 SQL이 직관적입니다. 그래서 오늘은 SQL로.

CHOICE · 오늘의 데이터베이스

우리의 선택 — Supabase

왜 Supabase

  • 무료 — 수업·개인 프로젝트엔 무료 티어로 충분
  • SQL — 표가 스프레드시트처럼 눈에 보임
  • 백엔드 서버를 따로 안 만들어도 됨 (BaaS)

내 앱이 Supabase에 바로 연결 — 서버 코드 없이.

Supabase가 해주는 3가지

  • 데이터베이스 — 메모를 담는 표
  • CRUD 연결 — 추가·조회·수정·삭제 통로
  • 로그인 — 구글 로그인까지 내장

메모장에 필요한 게 — 도구 하나에 다 들어 있음.

"백엔드"는 보통 따로 만들어 띄우는 서버지만 — Supabase 같은 서비스(BaaS)를 쓰면 그 서버 없이 앱이 바로 데이터에 연결됩니다.

TIP · 화면이 막힐 때

말로 설명이 어렵다면 — 화면을 찍어서 보여준다

스크린샷 — 두 단계

  1. Windows + Shift + S — 화면에서 필요한 부분만 드래그해 캡처
  2. Alt + V — Claude Code 입력창에 그 이미지를 붙여넣기
  3. Claude가 화면을 직접 보고 — "이 버튼을 누르세요" 안내

Supabase 설정 화면처럼 — 말로 풀기 번거로운 건 그냥 보여주세요.

다만 — 비용 트레이드오프

이미지는 글자보다 훨씬 많은 비용(토큰)이 듭니다 — 편하지만 공짜가 아닙니다.

  • 편하다고 매번 화면을 통째로 — X
  • 필요한 부분만 작게 잘라 찍기
  • 글로 될 일은 글로, 막힐 때만 이미지로

"보여주기"는 강력한 카드입니다 — 다만 비싸니, 막혔을 때의 비상 수단으로 아껴 쓰세요.

SUBAGENT · 도우미

서브에이전트 — 파일 하나가 도우미 하나

왜 + 무엇

메모장 하나에도 화면·데이터·로그인이 섞입니다. 한 대화에 다 시키면 맥락이 엉키죠 — 역할을 떼어 도우미에게 맡깁니다.

  • .claude/agents/의 .md 파일 하나 = 도우미 하나
  • 역할·규칙·쓸 모델을 사람 말로 적음
  • 메인 대화는 깨끗하게 — 위임 작업은 따로
.claude/agents/ui-helper.md
--- name: ui-helper--- model: sonnet너는 화면 담당이다. 단순하고깔끔한 메모장 화면을 만든다.기능은 적게, 보기 쉽게.

CLAUDE.md·슬래시를 써본 그 감각 그대로 — 사람 말로 역할을 적으면 도우미가 됩니다. /agents로 만듭니다.

CALL · 부르는 두 가지 방법

알아서 위임 — 또는 @로 지목

자동 위임

Claude가 알아서 부른다

  • 요청 내용이 어떤 도우미와 맞으면 — 알아서 위임
  • "메모장 화면 만들어줘" → 화면 도우미가 호출
  • 도우미 설명을 잘 적어둘수록 정확
@멘션 — 명시 호출

내가 직접 지목한다

  • @ui-helper 메모 입력칸 만들어줘
  • 어떤 도우미에게 맡길지 확실할 때
  • 1일차에 배운 @ 문법 그대로

처음엔 @멘션으로 명시 호출이 편합니다 — 누가 일했는지 눈에 보여서 감을 잡기 좋습니다.

HOW · /agents 로 만든다

도우미는 — /agents로 만들고 관리

  • 새 도우미 만들기 — 이름·역할·모델

만든 도우미는 .claude/agents/ 폴더에 파일로 남습니다 — Git에 커밋하면 그대로 보관·공유됩니다.

MULTI-AGENT · 한 명 → 한 팀

도우미 한 명 — 또는 한 팀

서브에이전트

직원 한 명에게 일 시키기

  • 격리된 자리에서 혼자 — 메인 대화는 안 어지럽힘
  • 보통 한 번 실행하고
  • 끝나면 결론 하나만 돌려주고 종료
멀티에이전트

팀을 꾸려 분업·협업

  • 여러 도우미가 동시에 — 병렬로
  • 오래 걸리는 일은 뒤로 돌리고 — 백그라운드
  • 도우미끼리 메시지를 주고받으며
  • 공유 작업목록으로 일을 나눠 맡음

멀티에이전트도 결국 구성원은 서브에이전트 — 도우미 하나(부품)를 여러 개, 한 팀으로 쓰는 패턴입니다. 곧 만들 메모장도 도우미 셋 = 작은 멀티에이전트.
