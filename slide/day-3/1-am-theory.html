WHY · Plan을 켜는 이유

DECISION · 계획서 앞에서 3선택

읽고 나서 3개 중 하나

Approve

계획대로 실행

의도와 맞으면 그대로 진행. Claude가 단계별로 작업 시작 — 중간 권한 prompt는 여전히 동작.

Edit

수정 요청

"3번 단계는 빼고" "auth는 다른 폴더에" — 메시지로 의도 전달 → 새 계획서.

Reject

거절

방향이 완전히 틀렸을 때. 거절 후 더 작은 단위로 다시 시키거나 다른 접근.

처음 며칠은 Edit를 자주 쓰게 됩니다 — 의도 정밀도가 올라가는 과정.

WHEN · Plan을 켜야 하는 순간

매번 X — 큰 변경 앞에서만

✓ Plan ON

의도 어긋나면 손해 큰 일

  • 여러 파일 동시 수정 (5개 이상)
  • 의존성 추가 · package.json 변경
  • 리팩터링 · 구조 변경
  • 잘 모르는 라이브러리 도입
  • 처음 해보는 작업
/ Plan OFF (interactive)

작은 단위 · 자주 하는 일

  • 한 파일 안에서 함수 1개 추가
  • 오타 수정 · 스타일 미세 조정
  • 여러 번 해본 동일 패턴
  • Q&A 성격의 질문

감이 안 오면 Plan ON이 정답. 잘못 켰을 때의 손해는 거의 없음 — 시간 1~2분만 더 들 뿐.

DEFINITION · Hook이 뭔가

Claude의 사이클 안에 끼어 넣는 자동 실행.

Day 1에 본 에이전트 5단계 사이클(요청·분석·계획·실행·검증)의 각 지점에 본인 셸 명령을 끼워 넣을 수 있습니다.

언제특정 이벤트가 일어날 때마다
무엇을본인이 정한 셸 명령 (curl · git · python 등)
결과알림 · 자동 lint · 자동 백업 등
CATALOG · 6 이벤트

Hook 이벤트 — 6가지가 있다 (외울 필요 X)

PreToolUse

도구 사용 전 — 차단·검증.
예) git commit 전 pytest 자동 실행

PostToolUse

도구 사용 직후 — 후속 작업.
예) 파일 저장 후 prettier 자동

Stop ★

응답 끝났을 때 — 오늘 만들 알림.
예) curl Telegram 한 줄 알림

UserPromptSubmit

사용자 메시지 보낼 때 — 검증·로깅.
예) 입력 길이 200자 제한

Notification

Claude가 알림 띄울 때 — UI 통합.
예) 권한 prompt를 데스크톱 알림으로

SubagentStop

서브 에이전트(Day 4) 작업 끝.
예) test-writer 끝 → 결과 요약 출력

PATTERNS · 자주 보는 3가지

실무에서 자주 쓰는 3가지 패턴

A

저장 시 lint

PostToolUse + 파일 저장 후 자동 lint. 코드 스타일 일관성. Day 4 도구 익숙해진 후 추가.

B

커밋 전 테스트

PreToolUse + git commit 전 pytest 자동. 테스트 깨지면 커밋 막음.

C ★

응답 끝 → 알림

Stop + curl Telegram. 오늘 직접 만듭니다 — 가장 단순하고 가장 유용.

A·B는 "있다"만 알아두기. C 하나로 Hook의 본질을 익힙니다.

CONFIG · .claude/settings.json

Hook은 JSON 한 파일로 정의

.claude/settings.json — Stop 훅 한 개
{ "hooks": { "Stop": [ { "matcher": "", "hooks": [ { "type": "command", "command": "curl.exe -s -X POST ..." } ] } ] }}

파일 위치: 프로젝트 루트의 .claude/settings.json. 실습에서 이 파일을 직접 만듭니다 — 외우지 않아도 OK, 따라 적기만.

EXAMPLES · 손에 익혀둘 3개

실무에서 가장 자주 보는 Hook 3가지

① Stop · 응답 끝 알림 ★

긴 작업 시키고 다른 일 → 휴대폰 알림 → 복귀.

"Stop": [{ "hooks": [{ "command": "curl.exe ... api.telegram.org/bot.../ sendMessage" }]}]

② PostToolUse · 저장 후 포맷

파일 저장될 때마다 자동 포맷 → 일관성 ↑.

"PostToolUse": [{ "matcher": "Write|Edit", "hooks": [{ "command": "prettier --write $FILE" }]}]

③ PreToolUse · 커밋 전 테스트

git commit 직전 pytest — 깨지면 커밋 차단.

"PreToolUse": [{ "matcher": "Bash", "hooks": [{ "command": "pytest", "blocking": true }]}]

오늘은 ① Stop 알림 한 개만 실습. ②·③은 익숙해진 후 본인 워크플로우에 맞춰 추가.

GOTCHA · PowerShell의 curl

PowerShell의 curl은 가짜 — Invoke-WebRequest의 alias

× 그냥 curl
command: "curl -X POST ..."
↓
PowerShell에선 Invoke-WebRequest 호출됨
인자 형식이 달라서 → 에러

Linux/Mac 예제를 그대로 복사하면 동작 X.

✓ curl.exe 또는 Invoke-RestMethod
command: "curl.exe -X POST ..."
또는
command: "Invoke-RestMethod ..."

curl.exe는 진짜 curl 실행 파일을 명시적으로 호출.

Windows에선 curl.exe로 시작 — 5일 내내 이 패턴 반복됩니다.
