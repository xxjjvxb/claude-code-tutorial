후보 1

/review

현재 변경 코드 리뷰. 보안·성능·가독성. 가장 안전한 첫 슬래시.

후보 2

/commit-msg

git status 확인 후 commit 메시지 한 줄 제안.

후보 3

본인 자주 쓰는 것

"테스트 짜줘" "문서 정리" 등 본인 패턴이 있으면 그걸로.

못 정하겠으면 /review로. 가장 활용도 높음 + 처음 슬래시로 적합.

A · 작성

.claude/commands/review.md — 직접 작성

.claude/commands/review.md — 예시
---description: 코드 리뷰 — 보안·성능·가독성 순으로 평가---# 코드 리뷰현재 git status로 변경된 파일 (또는 $ARGUMENTS)을다음 순서로 검토:1. **보안** — SQL injection · 시크릿 노출 등2. **성능** — 불필요한 루프 · DB N+1 등3. **가독성** — 변수명 · 함수 길이각 항목 1~3줄 코멘트 + 라인 번호. 한국어로.

파일 만들면 즉시 인식 — claude 재시작 불필요. / 입력하면 자동완성에 등장.

A · 5번 사용

정말 도움 되나 5번 사용해서 검증

1

현재 작업 중인 파일에 → /review

2

결과 보고 — 진짜 유용한 코멘트 나오는지 확인

3

아쉬우면 — review.md 본문 다듬기 (반복)

4

5번 정도 사용해서 → 본인에게 맞는 슬래시로 정착

5

git commit "커스텀 슬래시 /review 추가"

한 번 만들고 끝 X — 5번 쓰면서 다듬기가 핵심. 처음 만든 게 곧장 완성형은 거의 없음.
