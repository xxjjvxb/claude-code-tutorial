PART A · GIT 안전벨트

Git — 망쳐도 되돌릴 수 있다

AI가 파일을 마음대로 고치는 시대일수록 버전 관리는 옵션이 아니라 필수. 명령 4개만 있으면 충분합니다.

4핵심 명령
1되돌리기 명령
DEFINITION · Git이 뭔가

코드의 시간여행 장치입니다.

파일이 어떻게 바뀌어 왔는지 기록하고, 원하는 시점으로 되돌릴 수 있는 도구. 여러 명이 같이 작업할 때도 충돌 없이 합쳐줍니다.

기록파일이 변할 때마다 스냅샷으로 저장
복원"3시간 전으로 돌려줘" — 한 줄이면 끝
협업여러 명의 변경을 충돌 없이 합치기
WHY · AI 시대의 Git

AI가 파일을 직접 고치는 시대 — 안전벨트입니다

× Git 없이 AI 시키기
"여러 파일 한꺼번에 수정해줘"
✓ 5개 파일 수정 완료
...어 뭔가 망가짐
어디부터 어디까지 바뀐 건지 모름
되돌릴 길이 없음

한 번 잘못 시키면 복구 불가. 손이 떨리면서 일을 시키게 됩니다.

✓ Git과 함께
git commit (직전 상태 저장)
"여러 파일 한꺼번에 수정해줘"
✓ 5개 파일 수정 완료
망가졌으면 → git restore .
5초 만에 직전으로 복귀

되돌릴 수 있다는 감각이 있을 때만 AI에게 큰 일을 맡길 수 있습니다.

CONCEPT · 헷갈리지 말 것

Git ≠ GitHub — 완전히 다른 것

Git · 도구 (내 컴퓨터에)

버전 관리 프로그램 자체

  • 내 컴퓨터에서 동작
  • 인터넷 없이도 됨
  • 명령어: git init, git commit
  • 오픈소스 · 누구나 무료
GitHub · 서비스 (인터넷에)

Git 저장소를 클라우드에 두는 곳

  • 웹사이트 — github.com
  • 여럿이 같은 코드를 공유
  • Microsoft 운영 (유료/무료)
  • "Git의 인스타" 같은 SNS 측면도

오늘은 Git만 배우고, GitHub 가입까지만 합니다. 본격적으로 push/pull은 미니프로젝트 때.

CORE FLOW · 핵심 흐름

매일 쓰는 Git 명령은 딱 4개

01
init
한 번만. 폴더를 Git으로 추적 시작.
PS> git init
02
status
"지금 어떤 변화가 있나" 확인.
PS> git status
03
add
저장할 파일들을 모은다.
PS> git add .
04
commit
스냅샷 + 메시지로 영구 저장.
PS> git commit -m "메시지"

02 → 03 → 04 사이클이 매일 반복됩니다. 작업 한 덩어리 끝날 때마다 commit — 하루에 5–10번 정도.

DEEP · git init / git status

시작하고, 확인하는 명령

git init — 한 번만

현재 폴더를 Git이 추적하는 저장소로 만든다. 숨김 폴더 .git이 생성됨.

  • 이미 init된 폴더에 또 하면 → 그냥 무해함
  • .git 폴더 지우면 → 추적 끝
PowerShell — Day1/
PS> git init Initialized empty Git repository in C:\Users\you\Desktop\Day1\.git\PS> git status On branch main No commits yet Untracked files: about.html style.css

git status는 막혔을 때 가장 먼저 치는 명령 — 지금 상태가 어떤지 알려줍니다.

DEEP · git add / git commit

변경사항을 스냅샷으로 저장

add — 저장할 파일 모으기

변경된 파일 중 커밋에 포함시킬 것들을 선별해서 staged 영역에 올린다.

  • git add . — 모든 변경 다 포함
  • git add about.html — 특정 파일만

commit — 영구 저장

staged 영역의 내용을 스냅샷으로 박제. 메시지 한 줄 필수.

  • -m "메시지"로 한 줄 설명
  • 좋은 메시지: "자기소개 페이지 첫 버전"
한 사이클 — add → commit
PS> git add .PS> git commit -m "자기소개 페이지 첫 버전" [main (root-commit) a3f1b2c] 자기소개 페이지 첫 버전 2 files changed, 124 insertions(+)
UNDO · 되돌리기

망친 파일 한 줄로 원복.

commit 이후의 변경을 직전 commit 상태로 되돌리는 명령. AI가 잘못 고친 직후 가장 자주 씁니다.

파일git restore about.html — 그 파일만
전부git restore . — 모든 변경 통째 취소
규칙commit하지 않은 변경은 한 번에 사라짐 — 신중히

STEP 04 · @ 멘션

STEP 05 · ! 셸 실행

대화 중간에 PowerShell 호출

claude — Day1/
# 1) 셸 명령 즉석 실행> !git log ⚠ Claude wants to run: git log [ Allow once / Always allow / Deny ] → "Allow once" 선택 $ git log commit a3f1b2c (HEAD -> main) Date: ... 자기소개 페이지 첫 버전# 2) 그 결과 활용> 방금 git log 결과 보고, 다음 작업 제안해줘 현재 첫 커밋만 있네요. 다음 단계로: · style.css에 hover 효과 추가 · 두 번째 커밋으로 분리해 저장

처음 !를 쓰면 권한 prompt가 뜹니다 — "Allow once"가 가장 안전. "Always allow"는 나중에 신뢰가 쌓인 명령에만.

claude — Day1/
> 지금까지 작업 커밋해줘 변경 사항을 확인합니다. ⚠ Claude wants to run: git status → 승인 CLAUDE.md에 답변 규칙 3개 추가됨. 커밋 메시지를 제안드립니다: → "CLAUDE.md에 답변 규칙 추가" ⚠ Claude wants to run: git add . && git commit -m "..." → 메시지 OK? 승인 ✓ [main b8c9d4e] CLAUDE.md에 답변 규칙 추가 1 file changed, 4 insertions(+)

처음으로 AI가 본인 손 대신 git을 다루는 순간. 권한 prompt 뜨면 메시지 한 번 읽고 승인 — 무지성 X.

BONUS · 되돌리기 한 가지 더

AI가 망쳤을 때 — ESC 두 번

ESC 두 번이 하는 일

  • claude 대화 중 ESC를 두 번 누르기
  • Claude가 편집한 파일이 편집 직전 상태로 복원
  • 대화는 그대로 — 코드만 되돌아감
  • 커밋을 안 했어도 OK — 세션 안의 빠른 되돌리기

git restore와 무엇이 다른가

  • git restore — 마지막 커밋 시점으로
  • ESC 두 번 — Claude가 고치기 직전으로
  • 커밋 전이라 git restore가 못 잡는 변경도 ESC로
  • 둘 다 알아두면 어떤 상황에서도 되돌릴 수 있음

단, ESC 두 번은 Claude가 편집한 파일만 되돌립니다 — 본인이 직접 고친 것이나 터미널 명령의 결과는 대상이 아닙니다.
