자기소개 워밍업

셋업한 Claude Code로 첫 결과물을 만들어봅니다. 인터뷰 → 자기소개 대본 → HTML 페이지. 오늘 만든 결과물은 5일 내내 재활용 (Day 3에서 PPTX·PDF로 변환).

2미션
MISSION 1 · 진행 흐름

미션 1 — 3단계로 나눠서 진행

01

인터뷰 시작

"나를 인터뷰해서 자기소개 대본을 만들어줘" — Claude가 질문을 던지기 시작

02

답변하면서 대본 작성

5~7개 질문에 답하면 Claude가 자동으로 대본을 정리해서 제시

03

톤 변형 5가지로 다듬기

"더 짧게" "더 길게" "자신감 있게" "겸손하게" "공식적으로" — 한 줄씩 추가해서 결과 비교

막막하면 Claude에게 "먼저 어떻게 진행할지 계획부터 세워줘"라고 물어봐도 됩니다 — 메타 프롬프트.

INTERVIEW QUESTIONS · Claude가 던질 질문

이런 식으로 질문이 옵니다

Q1
이름과 직업·학생 신분이 어떻게 되시나요?
Q2
어떤 분야의 일·공부를 하고 계시나요?
Q3
본인의 강점이나 자신 있는 영역이 있다면?
Q4
취미나 평소 즐겨 하는 활동은 무엇인가요?
Q5
어떤 청중·상황에서 자기소개할 예정인가요?
Q6
대본 길이는 어느 정도 원하시나요? (1분/3분 등)

한 번에 다 답해도 되고, 하나씩 답해도 됩니다. "몰라요"도 답이 됩니다 — Claude가 대신 채워줍니다.

TONE VARIATIONS · 5가지

같은 내용, 다른 톤으로

짧게

"한 줄로 줄여줘"

길게

"3-4 문단으로 풀어 써줘"

자신감 있게

"강점을 분명하게 드러내서"

겸손하게

"좀 낮춰서 부드럽게"

공식적으로

"-습니다 체로 정중하게"

한 줄만 추가해도 결과가 완전히 달라집니다 — 점진적 구체화의 첫 경험. 5개 모두 한 번씩 시도해보세요.

RESULT COMPARISON · 톤별 결과

예: "디자인 일하는 김OO" — 3가지 톤

짧게

"안녕하세요, 디자인 5년차 김OO입니다. 사용자 경험 설계가 전공이고, 디자인 시스템 구축을 가장 잘합니다."

자신감 있게

"5년간 다양한 프로젝트에서 사용자 경험을 개선해온 디자이너 김OO입니다. 디자인 시스템 구축이라면 자신 있게 맡을 수 있습니다."

공식적으로

"안녕하십니까. 디자이너 김OO입니다. 5년간 사용자 경험(UX) 설계 분야에서 종사해왔으며, 특히 디자인 시스템 구축에 중점을 두고 있습니다."

같은 데이터인데 톤만 바꿔도 인상이 완전히 달라집니다. 발표 상황에 맞는 톤을 선택하는 감각을 기르는 것.

디자인 톤 변형 반복

"색을 더 따뜻하게" "사진 자리 추가" "마우스 hover 효과" — 한 줄씩 던지며 점진적 구체화

결과물이 매번 새로 생성됩니다 — 브라우저를 새로고침해서 변화 확인.

SHARE TIME · 발표 가이드

1분 안에 3가지만 보여주면 OK

20초

화면 띄우기

index.html을 브라우저로 열어 한 번 스크롤. 본인이 만든 페이지의 첫인상.

30초

한 줄 코멘트

"이런 톤으로 만들었어요" / "이 부분이 마음에 들었어요" / "이게 잘 안 됐어요" — 솔직하게.

10초

/usage 결과

/usage 한 번 확인 — 토큰·비용 감각의 시작.

완성도보다 "오늘 시도한 것"이 평가 기준. 못 만든 부분도 솔직히 — 그게 가장 좋은 발표. 발표자에게 청중 질문 1개씩 부탁드려요.
