# 주식 시뮬 실습 계획 — 7장 데스크톱 덱 재설계 (신고 104)

> 목표: AI 연동 없이, **로컬 PySide 프로그램이 서버 API와 통신**하는 경험.
> 강의자가 제공하는 "빠르게 움직이는 가상 주식 시장"에 수강생 각자가 만든 로컬 트레이딩 앱으로 접속해
> 시세 조회 → 매수/매도 → 수익 확인 → 리더보드 경쟁까지.

---

## 1. 교육 목표

| 기존 (클로드 펫) | 새 소재 (주식 시뮬) |
|---|---|
| PySide 창 + 캐릭터 디자인 | PySide 기본 창 + **실기능** |
| 로컬에서 끝남 | **API 통신** — 요청/응답, 키 인증, 폴링, rate limit |
| 혼자 결과 확인 | 리더보드 — 전원이 같은 시장에 참여 |

수강생이 얻는 것: "내 컴퓨터의 프로그램이 인터넷 서버와 대화한다"는 감각 + API 스펙 읽고 클라이언트 만드는 경험 (4장 공개 API의 심화 실전판).

## 2. 전체 아키텍처

```
[수강생 PC]                         [강의 인프라 — 기존 스택 그대로]
PySide 트레이딩 앱  ──HTTP──▶  Vercel API Routes (/api/stock/*)
  · 1초 폴링 시세                      │        ▲
  · 매수/매도 버튼                Supabase (주문·임팩트·키·리더보드)
  · 수익/차트 표시                     │
                                  강의자 대시보드 (웹 1페이지)
                                   · 실시간 차트 · 리더보드 · 체결 피드
```

- **추가 인프라 0** — 지금 쓰는 Vercel + Supabase 무료 스택 안에서 전부 해결.
- 강의자 화면은 사이트 안 웹페이지(`/stock-sim/board.html` 등) — 빔프로젝터로 상시 표시.

## 3. 가격 엔진 — 핵심 설계 결정

**"1초마다 움직이는 서버 프로세스"를 돌리지 않는다.** Vercel/Supabase 무료 플랜엔 상주 프로세스·초 단위 크론이 없음. 대신:

### 결정론적 가격 함수 (서버 무상태)
- `기준가(t) = f(SEED, floor(t))` — 시드 고정 랜덤워크를 **timestamp로 그때그때 계산**. 어떤 서버 인스턴스가 받아도 같은 t면 같은 가격.
- 레이어 구성: 장기 추세(사인 혼합) + 분 단위 변동 + 초 단위 노이즈. **5배속** 체감은 변동성 파라미터로 (실제 하루 장세 폭을 ~5분에 경험하는 수준으로 튜닝).
- 가상 거래량도 같은 방식으로 결정론 생성 — 참여자가 없어도 시장이 "혼자 시뮬레이팅".

### 참여자 임팩트 (상태는 이것만 저장)
- 주문 체결 시 `impacts` 테이블에 기록: (t, 방향, 수량, 강도).
- `실제가(t) = 기준가(t) + Σ 임팩트(감쇠 적용)` — 큰 매수는 가격을 잠깐 밀어올리고 수 분에 걸쳐 감쇠. 참여자 거래는 거래량에도 합산.
- **1시간 롤링**: 1시간 지난 임팩트는 무시/삭제. 기준가는 저장이 필요 없으므로 히스토리도 "요청 시 계산 + 임팩트 오버레이"로 즉석 생성.

### 부하 처리
- `GET /price`, `GET /history`는 CDN 캐시 `s-maxage=1` — 30명이 1초 폴링해도 오리진 호출은 초당 ~1회로 흡수.
- 주문/포트폴리오/리더보드만 DB를 침 — 빈도 낮음.

## 4. API 스펙 (v1 초안)

인증: 모든 요청 헤더 `X-API-Key: <발급 키>` · Base URL `https://vibe.219.co.kr/api/stock`

| 메서드 | 경로 | 설명 | 응답 예시 |
|---|---|---|---|
| GET | `/price` | 현재가·현재 거래량 | `{"t":1787130000,"price":10234.5,"volume":152}` |
| GET | `/history?seconds=300` | 최근 N초(≤3600) 초 단위 시세·거래량 배열 | `{"series":[{"t":...,"price":...,"volume":...},...]}` |
| POST | `/order` | 매수/매도 `{"side":"buy","qty":10}` — 시장가만 | `{"filled":10,"exec_price":10241.2,"slippage":0.07,"cash":...,"position":...}` |
| GET | `/portfolio` | 내 현금·보유수량·평가액·수익률·체결 내역 | `{"cash":...,"position":...,"value":...,"pnl_pct":...,"trades":[...]}` |
| GET | `/leaderboard` | 상위 N명 (이름·수익률) | `{"rows":[{"name":"길동","pnl_pct":12.3},...]}` |

- **Rate limit**: 키당 `GET 5회/초 · POST /order 1회/초` (스펙에 명시, 초과 시 `429`). 수강생이 "스펙의 제한을 지키는 클라이언트"를 짜보는 것 자체가 학습 포인트.
- 체결 모델(슬리피지): `체결가 = 현재가 × (1 ± k·qty)` + 가격 임팩트 등록. qty 클수록 불리 — "몰빵의 대가"를 몸으로 배움.
- 시작 조건: 키 발급 시 가상 현금 지급(예: 1,000,000). 공매도 불가(1차 버전), 잔고 내 매수만.

## 5. API 키 발급·배포

- `api_keys` 테이블: `key(uuid) · name(표시 이름) · cash · position · created_at`.
- **강의자료에서 제공**: admin.html에 "키 발급" 섹션 추가 — 이름 입력 → 키 생성 → 목록 표시. 수업 때 이름표처럼 나눠주거나, 열람 승인된 수강생 명단에서 일괄 발급.
- 키 = 계정. 앱에 키만 넣으면 이름·잔고가 따라옴 ("이름 기반 API 통신").

## 6. 강의자 대시보드 (웹 1페이지)

- 실시간 차트(1초 갱신, 최근 N분) + 거래량 바 + **매수/매도 체결 마커**(누가 어디서 샀는지 점으로)
- 리더보드 (수익률 순, 5초 갱신)
- 최근 체결 피드 ("길동: 10주 매수 @10,241")
- 강의자용 컨트롤(관리자 로그인 시): **라운드 리셋**(전원 잔고 초기화 + 임팩트 클리어 + 시드 변경)

## 7. 수강생 클라이언트 (PySide) — 실습 목표물

단계별로 커지는 구성 (덱 흐름과 1:1):

1. **v1 시세 뷰어**: 키 입력 → 1초 폴링 → 현재가 라벨 (QTimer + requests)
2. **v2 차트**: `/history`로 최근 5분 라인 차트 (QPainter 직접 그리기 — 외부 차트 라이브러리 없이. pyqtgraph 의존성 추가는 피함)
3. **v3 트레이딩**: 수량 입력 + 매수/매도 버튼 + 내 수익률 표시 + 내 체결 포인트를 차트에 마커
4. **v4 빌드**: PyInstaller로 .exe — 기존 덱의 빌드 파트 그대로 재사용

전 과정 "3문장 프롬프트 → Claude가 .py 생성 → 실행 → 빌드" 흐름 유지. API 스펙 표를 슬라이드로 주고 **"이 스펙대로 통신하는 앱을 만들어달라"**고 Claude에게 시키는 것이 핵심 프롬프트.

## 8. 전략 체험 (제공 예제 프롬프트 3~4개)

앱 완성 후 "전략 버튼 추가" 실습 — 각자 골라서 자동매매 한 판:

- **모멘텀**: 최근 30초 수익률 > +x% → 매수, < −x% → 매도
- **역추세**: 급락 시 매수, 급등 시 매도
- **거래량 신호**: 거래량 급증 + 상승 → 매수 / 급증 + 하락 → 청산
- **손절/익절**: 진입가 대비 ±y% 자동 청산

수동 트레이더 vs 자동 전략이 같은 리더보드에서 경쟁 — 수업 마지막 10분 하이라이트.

## 9. 7장 덱 재구성안 (18장 → 약 17~19장)

1. 커버 — "내 PC에서 도는 트레이딩 앱"
2. 지금까지 → 이번 장 (웹페이지 → 데스크톱 프로그램)
3. 이번 장에서 만들 것 — 데모 캡처 (강의자 완성본)
4. 데스크톱 프로그램이란 (기존 유지)
5. 도구 2개 — PySide(창) + PyInstaller(묶기) (기존 유지, "묶는다" 표현)
6. 설치 — Claude에게 부탁 (기존 유지)
7. **시장 소개** — 강의자 대시보드 화면 + "1초마다 움직이는 가상 시장, 여러분 거래가 가격을 밀고 당김"
8. **API 스펙** — 엔드포인트 표 + 키 + rate limit (이 슬라이드가 실습의 명세서)
9. **API 키 받기** — 각자 키 확인·보관
10. v1 시세 뷰어 — 3문장 프롬프트
11. v2 차트 — 프롬프트 + 결과 캡처
12. v3 매수/매도 + 수익 — 프롬프트 + 결과 캡처
13. 슬리피지 체험 — "몰빵 한 번 해보세요" (교육적 순간)
14. 전략 버튼 — 예제 전략 골라 붙이기
15. PyInstaller 빌드 → .exe (기존 유지)
16. 리더보드 타임 — 전원 경쟁 + 공유
17. WRAP — "로컬 프로그램이 세상과 통신한다"

## 10. 확정 사항 (2026-08-19 사용자 결정)

1. **종목 3개** — A(기준가 10,000) · B(25,000) · C(500), 시드 다른 랜덤워크
2. **수수료 없음 · 공매도 없음** · 시작 자금 1,000,000 · 라운드 리셋은 대시보드 관리자 버튼
3. **키 발급 = 열람 계정 연동** — 승인된 수강생이 `/slide/stock-sim/key.html`에서 "발급" 버튼 (게이트 뒤, 본인 키 재표시)
4. **대시보드 한 화면** (`/slide/stock-sim/board.html`) — 3종목 주가+거래량+체결 마커 차트, 참여자 수익률 곡선(최근 1시간), 리더보드, 체결 피드, 관리자 리셋
5. **엔진은 Supabase SQL 함수 단일 소스** — 주문 RPC가 서버가로 원자 체결(클라이언트 가격 조작 불가), Vercel 라우트는 CDN 캐시 씌운 씬 프록시

## 10b. 남은 고려사항

**기술 리스크**
- **rate limit의 실제 강제**: 서버리스에서 키당 초당 카운트는 정확 강제가 어려움 — Supabase에 최근 요청 기록 후 근사 판정(약간의 오차 허용) 또는 "스펙 준수는 신뢰 기반 + 명백한 초과만 429". 교육 목적상 후자로 충분
- **시계 뒤틀림**: CDN 캐시 1초 + 클라이언트 폴링 타이밍으로 표시가 1~2초 어긋날 수 있음 — 교육상 무해, 스펙에 "약간의 지연 있음" 명시
- **동시 주문 경합**: 같은 키의 동시 주문은 Supabase 트랜잭션/단일 UPDATE로 처리 (qty 검증 포함)
- **차트 구현 난도**: QPainter 라인차트는 Claude가 잘 뽑지만 수강생 환경에서 고DPI 등 변수 — 강의자 검증 버전 코드를 백업으로 준비
- **방화벽/사내망**: HTTPS 아웃바운드만 쓰므로 대체로 통과 — 현장 사전 테스트 1회 필요
- **부정행위**: 키 공유·타인 키 사용 가능 — 교육용이므로 무시 (리더보드 이름만 관리)

**공수 추정**
- 서버(API 5개 + 가격엔진 + 대시보드 + admin 키 발급): 1~2일 분량
- 덱 재구성(17장 내외, 캡처 제외): 반나절
- 현장 리허설(부하·방화벽·빌드 동선): 별도 1회 필수

## 11. 구현 순서 (제안)

1. 가격 엔진 + `/price`·`/history` (CDN 캐시 포함) → 대시보드 차트로 눈 확인
2. 키 발급(admin) + `/order`·`/portfolio` + 슬리피지·임팩트
3. `/leaderboard` + 대시보드 완성(체결 마커·피드·리셋)
4. 수강생 클라이언트 v1~v4 레퍼런스 구현 (강의자 검증본 + 캡처 확보)
5. 7장 덱 재구성 + API 스펙 슬라이드
6. 리허설 → 파라미터 튜닝(변동성·슬리피지 계수·시작 자금)
